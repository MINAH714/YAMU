# EXP-002 — LOCA LIKIT Eat 추가

## 사전 계획과 승인

사용자는 첫 실험 원본을 보존하고, 같은 24건의 금액·가맹점·시각·순서에 등록 카드 한 장만 추가하도록 요청했다. 후보·사전 검사·보존·전체 기록 점검 계획을 제시했고, 사용자가 LOCA LIKIT Eat으로 구현·실행을 승인했다. 이 문서는 완료 후 승인된 조건과 결과를 함께 정리한 기록이다. 결과 확인 이전에 만든 입력은 실행 폴더의 frozen-extension.json과 소스 ZIP에 남아 있다.

선정 이유는 기존 등록 정책의 음식점·카페 60% 할인 및 월 13,000원 공유 한도다. 음식점 기회와 공유 한도 경쟁을 추가할 수 있고, 등록된 실적 인정·귀속 규칙이 기존 국내 일반 구매 범위를 지원한다. 카드는 결과 확인 후 교체하지 않았다. 운영 DB 적재나 카드사 실제 지급을 검증한 것은 아니다. 원시 시드의 일부 NULL은 이미 승인된 모의 정책으로 해석되며, 적용 규칙은 prepared-policies.json에 보존한다.

## 고정 조건

- [기존 입력](../exp-001-two-cards/frozen-input.json)의 SHA-256 `6893d7f66d13c8010623b499a4d07a9a660336f1c91bd7961f53de9d8cbf850c`를 실행 전에 검사.
- 카드 순서: 처음(0), 톡톡(1), LOCA(2). 기존 거래 24건·309,000원 유지.
- 세 카드 전월 실적 각각 400,000원, 당월 실적·한도 사용량 0, 가용 신용한도 각각 10,000,000원, ACTIVE/NORMAL. 기본 카드 처음 유지.
- 전략: 카드별 고정 3종, 음식점 LOCA/카페 톡톡/편의점·온라인쇼핑 처음, YAMU, 균등 랜덤.
- 랜덤은 java.util.Random, 시드 0~99, nextInt(3). 기존 nextInt(2)와 매핑은 다르며 transactions.csv의 selectedIndex에 실제 결과가 남는다.
- 기존 계산기·선택기·실적 해석기를 사용한다. 실적·금액 한도·가용 신용한도는 독립 장부에 선택 카드만 갱신한다. 등록된 횟수 한도는 0개이므로 횟수 소진 실증은 해당 없음이며 규칙을 만들지 않았다.

## 명시한 사실 보완

원본 2장 입력은 변경하지 않았다. 아래 값은 확장 입력의 additionalFacts로만 보완했다. 전부 보완 전에는 키가 없었고, 값은 false다. 정책의 미확정값을 대체하지 않았다.

| 코드 | 근거 |
|---|---|
| PERFORMANCE:INTRODUCTORY_WAIVER_ACTIVE:lotte-p13943-a13943 | 기존 카드와 같이 신규 유예가 끝난 가상 사용자 |
| PERFORMANCE:TELECOM_AUTOPAY | 음식·음료·일반 상품 구매는 통신요금 자동납부가 아님 |
| TRANSACTION_KIND:AUTO_SMART_CASHBACK | Auto/Smart Cashback 거래가 아닌 일반 상품 구매로 정의 |
| TRANSACTION_KIND:DISABLED_EMPLOYMENT_LEVY | 장애인고용부담금 납부가 아님 |
| TRANSACTION_KIND:POSTPAID_TRANSIT | 기존 PERFORMANCE:POSTPAID_TRANSIT=false와 동일 사실 |
| TRANSACTION_KIND:FINES_AND_PUBLIC_FEES | 벌금·공과금 납부가 아님 |

입력 안에 필드별 근거도 남겼다. 계획 승인 후 새로운 거래 사실 보완이나 미확정 정책 변경은 필요하지 않았다.

## 검사와 실행

[실행 폴더](../executions/run-2026-11-12T15-34-58.098810900Z-9db10134-5b83-4b4c-9881-6ff7b6a1b619/)에서 순서대로 수행했다.

1. 기존 두 카드 입력으로 104회 재현. 원본의 거래 선택·후보별 혜택·실적·한도 변화·총액과 일치. 생성 DB ID와 JSON 숫자 scale 차이를 정규화했다.
2. LOCA용 사실만 추가한 두 카드 입력으로 다시 104회 비교. 동일 기록 일치. 새로운 경제 효과 실험이 아니라 사실 보완 영향 검사다.
3. 세 카드에 대해 초기 상태 72개 카드 평가, 전체 한도 소진 및 개별 한도 잔여 1/소진 상태 검사. 총 288개 상태×3장=864개 사전 카드 평가가 정상 계산됐다. 전수 가능한 모든 상태 공간을 탐색했다는 뜻은 아니다.
4. 대표 수식: 음식점 12,000×60%=7,200원, 스타벅스 6,000×60%=3,600원, 공유 잔여 500원이면 500원 지급, 한도 소진 시 0원. LOCA의 GS25·쿠팡 일반 상품 0원도 정상 계산 확인.
5. 할인 거래 실적 0원·한도 소진 후 무할인 음식점 실적 12,000원, 처음의 일 한도 다음 날짜 초기화 및 월 한도 유지 확인.
6. 105회 본 비교. 7,560개 카드 평가에서 계산 불가 0건. YAMU 재실행도 동일. 승리 여부를 통과 조건으로 사용하지 않음.

JUnit 1건, 실패·오류·생략 0, 첫 확장 실행 성공. 각 단계의 validation.json, 검산 문서, 요약 CSV, 분포 및 raw-records.zip을 확인할 수 있다. 실행 명령과 복원 방법은 [색인](../README.md#재현)에 있다.

## 동률이 된 이유

두 전략 모두 처음 5,000P·톡톡 스타벅스 10,000원·LOCA 13,000원이라는 이 거래 범위의 관련 월 한도를 모두 활용했다. 합계 28,000원은 이 조건에서의 상한이다. 이것은 YAMU가 일반적으로 월간 최적을 보장한다는 증거가 아니다.

| 거래 | 업종 규칙 | YAMU | 해석 |
|---|---|---|---|
| 2: 11/2 스타벅스 | 톡톡 3,000원 | LOCA 3,600원 | YAMU가 즉시 600원을 더 받지만 LOCA 공유 한도를 먼저 사용 |
| 5: 11/6 음식점 | LOCA 5,800원 | LOCA 2,200원 | 앞선 카페 사용 때문에 YAMU의 LOCA 잔여 한도가 더 적음. 두 전략 모두 여기서 LOCA 소진 |
| 9·12: 11/11 음식점·쿠팡 | 0원·500P | 500P·0원 | 처음 일 한도의 사용 위치가 이동. 두 거래 합계는 동일 |
| 14: 11/16 스타벅스 | 톡톡 1,000원 | 톡톡 3,000원 | YAMU는 2번에서 톡톡을 쓰지 않아 잔여 한도가 더 많음 |
| 18: 11/21 스타벅스 | 톡톡 0원 | 톡톡 1,000원 | YAMU도 톡톡 월 한도까지 활용 |
| 21·23: 11/27 음식점·GS25 | 0원·150P | 100P·0원 | 앞선 누적 경로가 달라 개별 거래만으로 월 차이를 설명할 수 없음. 월 전체 처음 합계는 모두 5,000P |

카드 추가 전후 YAMU는 +13,000원 증가했지만 같은 세 카드에서 업종 규칙 대비 추가 효과는 0원이다. 카드 집합의 효과와 선택 방식의 효과를 합쳐 YAMU 자동 선택만의 성과로 주장하지 않는다.

## 범위와 이후 과제

합성 거래 한 묶음, 특정 카드 조합·정상 승인·전월 실적 충족 조건이다. 실물 결제·연회비·실제 포인트 환급액·사용 편의성·다음 달 실적 유지·외부 실패는 평가하지 않았다. 두 실험 모두 충분한 거래가 있어 관련 월 한도를 채웠다는 특성이 있다.

이번 확장은 여기서 종료했다. 다른 소비액·순서·실적 조건이나 다른 업종 규칙을 시도하려면 별도 사전 계획과 실험 ID가 필요하다. 동률을 없애려는 사후 거래·카드 교체는 수행하지 않았다.
