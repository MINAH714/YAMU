# EXP-001~005 종합 결론

2026-11-13 · [실험 색인](README.md) · [기록 점검표](record-audit.md)

## 실험 결과 요약

**YAMU는 결제할 때 카드별 혜택과 남은 한도를 계산해 카드를 골랐다. 하지만 다른 선택 방법보다 총혜택이 항상 높지는 않았다.**

EXP-001~005에서 확인한 주요 결과는 다음과 같다.

- **혜택표로 직접 계산하는 규칙과 YAMU의 총혜택은 같았다.** 가상 거래를 사용한 12개 조건에서 선택한 카드도 같았다. 여기서 직접 계산은 사람이 수행한 것이 아니라, 정해진 계산 규칙을 코드로 구현한 것이다.
- **업종별 고정 사용보다 불리한 경우도 있었다.** 여러 업종이 함께 쓰는 혜택 한도를 앞선 거래에서 먼저 사용하면, 뒤 거래의 혜택이 줄어 월 총혜택이 낮아질 수 있었다.
- **실제 거래 내역에서는 계산된 포인트가 150~165P 늘었다.** 58건 중 실제 사용 카드와 YAMU의 선택이 다른 거래는 1건이었다. 이 수치는 확인된 정보와 승인된 가정으로 계산한 값이며, 카드사가 실제 지급한 포인트는 아니다.

이번 실험에서는 **카드 선택 방법에 따라 총혜택이 얼마나 달라지는지** 확인했다. 실제 사람이 YAMU를 사용했을 때 선택 시간이 줄거나, 덜 번거롭거나, 실수가 줄어드는지는 아직 측정하지 않았다.

## 실험별 비교 내용과 결과

EXP-001~004에서는 실험용으로 만든 가상 거래 24건·총 309,000원을 사용했다. 보유 카드 수와 거래 금액을 바꾸면서 카드 선택 방법별 총혜택을 비교했다. EXP-005에서는 실제 거래 내역에 대해, 실제 사용 카드로 계산한 혜택과 YAMU가 고른 카드로 계산한 혜택을 비교했다.

| 실험 | 비교 내용 | 결과 |
|---|---|---|
| [EXP-001](exp-001-two-cards/README.md) | 카드 2장을 보유했을 때 선택 방법별 총혜택 | YAMU = 업종별 고정 **15,000원**. 랜덤 평균 12,736원 |
| [EXP-002](exp-002-three-cards/README.md) | 같은 거래에 LOCA LIKIT Eat을 추가했을 때 총혜택 | YAMU = 업종별 고정 **28,000원**. 랜덤 평균 21,350원 |

| [EXP-004](exp-004-manual-table/README.md) | 혜택표와 남은 한도로 계산해 고르는 방법과 YAMU 비교 | **12조건 모두 YAMU와 동률**. 선택한 카드와 거래 후 남은 한도도 같음 |

EXP-002에서 2장 대비 늘어난 13,000원은 **보유 카드가 달라진 효과**다. 카드를 추가해서 늘어난 혜택을 YAMU가 카드를 더 잘 골라서 얻은 혜택이라고 설명하면 안 된다.

가상 거래 실험은 카드별 전월 실적 400,000원, 월초에 사용한 혜택 한도 0, 모든 카드로 결제할 수 있는 상태에서 시작했다. 카드 수 2가지(2장·3장)와 거래 금액 비율 6가지(10·15·25·50·75·100%)를 조합한 것이 ‘12개 조건’이다. 12명을 대상으로 실험했다는 뜻이 아니다. EXP-004도 이 조건을 그대로 사용했으므로 새로운 사용자나 새로운 거래 사례가 추가된 것은 아니다.

### 실험에서 비교한 카드 선택 방법

| 이름 | 카드를 고르는 방법 |
|---|---|
| 카드별 고정 사용 | 모든 거래를 특정 카드 한 장으로 결제 |
| 균등 랜덤 | 모든 카드가 같은 확률로 선택되도록 무작위로 고름. 같은 결과를 다시 확인할 수 있도록 난수 시작값(시드) 100개를 미리 정해 100회 반복 |
| 업종별 고정 사용 | 업종마다 사전에 정한 카드를 사용. 한도가 소진돼도 전환하지 않음 |
| 혜택표 기반 수동 선택 | 카드별 예상 혜택에 잔여 한도 등을 반영하고, 현재 혜택이 가장 큰 카드 선택 |
| YAMU | 서비스에 구현된 추천 기능으로 이번 거래에 사용할 카드를 선택 |

EXP-004의 ‘수동 선택’은 **사람이 혜택표를 보고 계산하는 방법을 코드로 구현한 것**이다. 실제 참여자가 카드를 고른 실험은 아니다. ‘혜택이 1원이라도 남으면 같은 카드를 유지한다’는 이전 제안은 사용하지 않았다. 모든 선택 방법은 이번 거래와 이전까지의 사용 내역만 확인하며, 이후에 발생할 거래를 미리 보지 않는다.

## 총혜택이 같거나 YAMU가 더 적었던 이유

### 1. 혜택표로 계산하는 규칙과 YAMU는 같은 카드를 골랐다

EXP-004의 수동 선택 코드는 YAMU의 추천 결과를 사용하지 않았다. 혜택표와 현재까지 사용한 한도로 카드별 예상 혜택을 계산한 뒤, 예상 혜택이 가장 큰 카드를 골랐다. 선택 후에는 다른 방법과 동일한 서비스 혜택 계산기로 혜택 금액을 확인했다.

12개 조건에서 총 288번 카드를 선택했으며, 매번 YAMU와 같은 카드를 골랐다. 거래 후 남은 한도도 같았다. 각 거래에서 사용할 수 있는 카드의 혜택을 확인한 총 720건에서, 혜택표로 예상한 금액과 서비스 계산기가 산출한 금액의 차이는 모두 0원이었다. 여기서 ‘실제 혜택’은 계산기 산출액이며 카드사 지급액이 아니다.

따라서 **이 카드와 거래에서는 혜택표를 정확히 계산하는 규칙과 YAMU의 선택이 같았다**고 말할 수 있다. 실제 사람보다 더 많은 혜택을 얻거나 더 빠르다는 뜻은 아니다.

### 2. 일부 거래 금액에서는 업종별로 정해 둔 카드를 쓰는 편이 총혜택이 높았다

카드 3장을 보유한 조건의 결과는 다음과 같다. ‘거래 금액 비율 25%’는 원래 각 거래 금액을 25%로 줄였다는 뜻이다. 할인과 포인트는 기존 실험의 환산 기준에 따라 원 단위로 합산했다.

| 원래 거래 금액 대비 비율 | 업종별 고정 사용 | YAMU와 수동 선택 | YAMU − 업종별 고정 |
|---|---:|---:|---:|
| 10% | 7,600 | 7,980 | +380 |
| 15% | 11,398 | 11,968 | +570 |
| 25% | 18,998 | 17,285 | **−1,713** |
| 50% | 26,825 | 24,750 | **−2,075** |
| 75% | 28,000 | 28,000 | 0 |
| 100% | 28,000 | 28,000 | 0 |

카드 2장에서는 여섯 가지 거래 금액 비율 모두 총혜택이 같았다. 전체 12개 조건 중 YAMU의 총혜택이 업종별 고정보다 **높은 조건은 2개, 같은 조건은 8개, 낮은 조건은 2개**였다. 이것만으로 일반 사용자에게도 같은 비율로 유리하거나 불리하다고 판단할 수는 없다.

차이가 난 이유는 **여러 업종이 함께 사용하는 혜택 한도를 어떤 거래에서 먼저 썼는지**가 달랐기 때문이다. 이를 ‘공유 한도’라고 한다.

- **25%:** YAMU는 앞선 커피 거래에서 LOCA를 선택해 총 600원을 더 받았다. 이후 음식점 거래에서 800원과 1,650원을 덜 받고 다른 카드로 137P를 받아, 최종 차액은 −1,713원이 됐다.
- **50%:** YAMU는 LOCA 공유 한도를 9번째 거래에서, 업종별 고정은 13번째 거래에서 소진했다. LOCA 합계는 같았지만 YAMU의 톡톡 혜택은 2,750원 적고 ‘신한 처음’ 카드 혜택은 675원 많아, 합계가 2,075원 낮았다.
- **10·15%:** 관련 월 한도를 모두 쓰지 않았기 때문에, 커피 할인율이 톡톡 50%보다 높은 LOCA 60%를 선택한 만큼 총혜택도 늘었다.

즉, **매번 그 거래에서 혜택이 가장 큰 카드를 골라도, 한 달 총혜택이 가장 커지는 것은 아니다.** 업종별 고정 사용은 이후 거래를 미리 보고 카드를 고른 것이 아니다. 미리 정해 둔 카드가 이 거래 순서에서는 더 많은 총혜택을 얻었을 뿐이다. 거래별 결과와 무작위 선택 100회의 결과는 [EXP-004 보고서](exp-004-manual-table/README.md)와 [전체 비교표](exp-004-manual-table/comparison.csv)에 남아 있다.

### 3. 실제 거래 58건 중 57건은 이미 YAMU와 같은 카드를 사용했다

EXP-005는 실제 거래 내역 **58건**을 Deep Dream 신용·체크 카드로 모의 비교했다.

실제로 사용한 카드는 신용 57건·체크 1건이고, YAMU는 58건 모두 신용카드를 골랐다. **이미 57건의 선택이 같았기 때문에**, 차이는 해외 체크 거래 한 건에서만 발생했다.

| 계산 조건 | 해외 거래의 포인트 계산에 사용한 금액 | 실제 사용 카드로 계산했을 때보다 늘어난 포인트 |
|---|---:|---:|
| A | 비공개 | +153~165P |
| B | 비공개 | +150~160P |

A/B 각각에 보너스 포인트를 함께 적용하는 방법 2가지와 소수점 이하 포인트를 버리는 방법 3가지를 적용했다. 확인되지 않은 정책을 한 가지로 단정하지 않고, 총 12개 조건에서 결과가 어떻게 달라지는지 비교했다. B는 실제로 확인된 수수료가 아니라 승인된 가정으로 적립 기준액을 조정했다. 원본 결제액은 바꾸지 않았다.

업종이 확실하지 않은 거래 32건은 가능한 업종으로 각각 계산해 보고, 여러 거래의 업종이 동시에 달라지는 경우도 확인했다. 이때도 혜택 한도가 남고 신용카드의 혜택이 더 크다는 것을 수식으로 확인해, 두 선택 방법의 차액이 유지되는지 검증했다. 가능한 업종 조합을 전부 실행한 것은 아니다. **업종을 어떻게 적용하느냐에 따라 총포인트는 달라지지만, 같은 조건에서 두 방법을 비교한 차액은 유지됐다.**

확인된 정보와 계산을 위해 가정한 내용은 구분해야 한다.

- 확인한 사실은 해당 혜택에 필요한 실적·자격 충족 여부 등이다.
- 모든 카드로 결제할 수 있고, 월초에 사용한 혜택 한도는 0이라고 가정했다. 거래 목록 밖에서 쓴 공유 한도는 제외했고, 상품권·충전 등이 아닌 일반 구매로 계산했다. 모두 사전에 승인한 가정이다.
- ‘챙겨드림’ 혜택은 아직 확정하지 못했고, 다음 달 실적도 계산하지 않았다. 따라서 결과는 **확인 가능한 항목까지만 계산한 포인트**이며, 실제 지급액이나 한 달의 최종 혜택은 아니다.

12개 조건은 **같은 거래 내역에 서로 다른 정책 가정을 적용한 것**이다. 사용자 12명이 YAMU를 사용한 결과가 아니다. 이 사례에서 포인트가 늘었다고 해서, 앞선 실험에서 수동 규칙과 같았거나 업종별 고정보다 낮았던 결과가 달라지는 것은 아니다.

## 발표에서 주장할 수 있는 범위

| 현재 말할 수 있는 것 | 아직 말할 수 없는 것 |
|---|---|
| 가상 거래 12개 조건에서 각 카드 고정 사용과 랜덤 100회 평균보다 혜택이 높았다 | 모든 랜덤 실행이나 모든 사용자에게 항상 더 유리하다 |
| 혜택표로 계산하는 규칙과 YAMU가 같은 카드를 골랐다 | 실제 사람보다 혜택이 높고 시간·수고·실수가 줄었다 |
| 선택 방식과 한도 사용 순서가 총혜택을 바꿀 수 있다 | YAMU가 월간 총혜택을 항상 최대화한다 |
| 실제 거래 내역 한 사례를 승인된 가정으로 계산했을 때 150~165P 늘었다 | 사용자가 실제로 그만큼 지급받았거나, 평균적으로 그만큼 절약한다 |
| 검증한 거래와 한도 소진 등의 상황에서 혜택과 거래 후 남은 한도를 다시 계산해 확인했다 | 모든 카드 정책과 실제 결제·지급 과정의 정확성을 검증했다 |

연회비와 해외 결제 비용을 빼고도 이익이 남는지, 다음 달 실적을 유지할 수 있는지는 이번 실험에서 확인하지 않았다. 실제 결제 승인, 동시에 들어온 결제 요청, 외부 서비스 장애 등도 검사 대상이 아니다.

모든 선택 방법의 혜택을 같은 계산기로 평가했지만, 그 계산기 자체에 오류가 있으면 결과가 함께 잘못될 수 있다. 대표 거래를 별도 수식으로 검산하고 한도가 소진되는 상황 등을 검사했으나, 카드사가 실제 지급한 금액과 대조한 것은 아니다.

### 발표용 문장

> YAMU는 결제할 때 카드별 혜택과 남은 한도를 계산해 카드를 고릅니다. 가상 거래 실험에서는 혜택표로 정확히 계산하는 규칙과 같은 카드를 골랐습니다. 하지만 일부 조건에서는 한도를 먼저 사용한 탓에, 업종마다 정해 둔 카드를 쓰는 방법보다 한 달 총혜택이 낮았습니다. 실제 거래 내역 58건을 계산한 사례에서는 한 건의 카드 선택이 달라져 포인트가 150~165P 늘었습니다. 이 금액은 확인된 정보와 사전에 정한 가정으로 계산한 값이며 실제 지급액은 아닙니다. 실제 사람의 선택 시간이나 부담이 줄어드는지는 이번 실험에서 확인하지 않았습니다.

## 실험 보고서와 이전 문서

이 문서는 결론을 읽기 쉽게 정리한 안내이며, 원본 실험의 수치·입력·코드·결과를 대체하지 않는다. 실사용자 후속 실험은 진행하지 않기로 했다. 시간·부담·실수 감소는 검증하지 않은 항목으로 남긴다.

- [실험 색인](README.md): EXP-001부터 EXP-005까지 입력·계획·결과 연결
- [기록 점검표](record-audit.md): 확인한 기록, 보완 사항, 남은 미확인 항목
- [EXP-005 실행 보고서](exp-005-deep-dream/execution/README.md): 정책 12조건, 대안 분석, 검산과 실행 이력

개인 거래 원자료와 이전 문서의 개인정보 포함 사본은 공개하지 않는다. 공개 범위는 개인정보 점검 기록을 참고한다. 확인되지 않은 과거 과정은 추정해서 작성하지 않는다. 최종 실행에서 계산하지 못한 거래가 0건이었다고 해서, 처음부터 모든 정보가 갖춰져 있었던 것은 아니다. 실패·정보 보완·재실행 이력은 각 실험 기록에 남아 있다.
