# EXP-006: 생활비 6개월에서 카드 선택 방법 비교

[전체 실험 색인](../README.md) · [사전 계획](plan.md) · [실행 이력](execution-history.md) · **[월별·누적 차액 표와 그래프](differences.md)**

6개월 합성 거래 **521건, 총 5,609,000원**에서 YAMU의 총혜택은 **69,800원**이었다. 처음만 사용했을 때보다 5,950원, 톡톡만 사용했을 때보다 11,300원 높았다. 이 금액은 월평균이 아닌 **6개월 전체 차액**이다.

발표에 사용할 결론:

> 선정한 두 카드와 6개월 합성 소비에서, YAMU는 톡톡 카드만 사용했을 때보다 혜택을 **11,300원, 약 19.3% 더 받았습니다.**

톡톡만 사용한 혜택 58,500원에서 YAMU 69,800원으로 증가한 결과다. 계산식은 `(69,800 − 58,500) ÷ 58,500 × 100 = 19.316…%`이며 소수점 첫째 자리로 반올림했다. **19.3%는 소비액 환급률이 아니라 톡톡만 사용했을 때의 혜택 대비 증가율**이다. 이 비교 대상을 모든 카드·모든 사용자에 대한 효과로 넓혀 표현하지 않는다. 다른 비교군과 불리한 결과도 아래에 그대로 공개한다.

사용자 요청에 따라 이전 EXP-006을 이 실험으로 교체했다. 이전 EXP-006 결과를 별도로 보존하거나 EXP-007을 만들지 않았다. EXP-001~005는 그대로다. 최종 승인 범위에 따라 실적 보장용 결제·강제 카드 배정은 넣지 않았으며, **두 카드의 실적이 매월 모두 충족된 실험은 아니다.**

YAMU의 소비액 대비 혜택은 **1.24%**다. 연회비·이자·외부 지출은 포함하지 않았으므로 실질 수익률이나 모든 비용을 뺀 이익으로 표현하지 않는다.

랜덤은 시드 0~99를 모두 사용했다. 최솟값 50,050원, P05 52,200원, 중앙값 61,625원, P95 70,750원, 최댓값 79,100원이었다. 모집단 표준편차는 6,009.94원이다. **9경로는 YAMU보다 높고, 91경로는 낮았다.** 동률은 없었다. P05·P95는 정렬한 100개 중 5번째·95번째 값이다. ## 소비를 늘렸는데 왜 두 카드 실적이 모두 충족되지 않았나

실적은 전체 소비액이 아니라 **각 카드로 결제한 금액 중 실적으로 인정되는 금액**이다. YAMU는 지금 거래의 혜택으로 선택하며 다음 달 실적을 채우기 위해 결제를 나누지 않는다. 혜택이 같으면 기존 로직에 따라 기본 카드인 처음을 선택한다. 톡톡으로 할인받은 거래는 기존 정책에서 실적 인정액이 0원이다.

11월 YAMU는 톡톡으로 할인받은 22,000원을 제외한 982,200원을 처음의 실적으로 쌓았다. 톡톡 인정 실적은 0원이어서 12월부터 혜택 자격이 없어졌고, 이후 YAMU는 전부 처음으로 결제했다. **거래 금액을 늘리는 것만으로 두 카드의 실적 충족이 보장되지는 않았다.**

반면 처음만·톡톡만 사용한 경로는 실제 사용하는 카드의 최소 실적 30만 원을 매달 충족했다. 사용하지 않는 카드의 실적 0원은 정상적인 결과다. 업종별 고정 사용에서는 카페 금액만 톡톡에 쌓여 매달 미달했다. [월별 실적과 다음 달 자격](runs/main-2026-11-13T08-12-30.835208800Z-001549c3-9328-424e-b65b-38762aadac1e/monthly-performance.csv)에 랜덤을 포함한 104경로를 기록했다.

## 차액이 생긴 이유

- **처음만 사용 대비 +5,950원:** 11월에는 YAMU가 톡톡 혜택을 함께 받아 10,000원 높았다. 그러나 처음만 사용한 경로는 11월 실적이 1,004,200원으로 100만 원 구간에 진입했다. YAMU의 처음 실적은 982,200원이라 12월 한도가 더 작았다. 12월 YAMU가 4,050원 낮아져 합계 차액은 5,950원이다. 1~4월은 동률이다.
- **업종별 고정 대비 +1,950원:** 11~3월은 총혜택이 같았다. 개별 거래에서는 YAMU가 카페 혜택을 먼저 받는 만큼 뒤의 다른 거래에서 한도가 줄어드는 일이 있었다. 4월에는 처음의 월 한도 20,000원이 남아 있어, 업종별 고정이 실적 미달인 톡톡으로 결제한 카페 8건을 YAMU는 처음으로 결제했다. 해당 8건의 200·250·350·150·250·300·250·200원이 합계 1,950원 차이를 만들었다. 거래 번호는 442·449·467·471·479·486·505·520이다.
- **랜덤 최고 경로 대비 −9,300원:** 시드 57은 우연히 두 카드의 최소 실적을 매달 충족했다. 12~3월에는 YAMU보다 총 14,600원 높았고, 4월에는 5,300원 낮아 6개월 합계는 9,300원 높았다. 최고 경로만을 일반적인 랜덤 성능으로 주장하지 않으며 100개 전체 분포를 함께 제시한다.

[거래별 차액](runs/main-2026-11-13T08-12-30.835208800Z-001549c3-9328-424e-b65b-38762aadac1e/transaction-differences.csv)과 [월별 차액](runs/main-2026-11-13T08-12-30.835208800Z-001549c3-9328-424e-b65b-38762aadac1e/monthly-differences.csv)은 합계와 일치하도록 검증했다. 후보별 계산, 선택 사유, 전후 실적, 후보 한도와 실제 차감은 [거래 기록 ZIP](runs/main-2026-11-13T08-12-30.835208800Z-001549c3-9328-424e-b65b-38762aadac1e/trades.zip)에 있다.

## 검증 결과와 해석 범위

- 사전 검사 18,756조합에서 계산 불가 0건, 정상 0원 16,884건. 6개 실적 구간과 미사용·부분 잔여·소진 한도를 검사했다.
- 본 실행 104경로 × 521건, 후보 계산 108,368건에서 계산 불가 0건. YAMU 반복 실행의 전체 기록 해시가 일치했다.
- 독립 수식으로 후보 혜택·선택·실적·한도 차감·랜덤 매핑을 검산했다. 대표 7,000원 스타벅스 거래는 처음 350원, 톡톡 3,500원이며 톡톡 할인 거래 인정 실적은 0원이다.
- 기존 EXP-001~005 보존 압축본 199개 항목의 해시가 일치했다. 서비스 코드와 기존 실험은 바꾸지 않았다.

실적 미달 때 생기는 적용 대상 밖 한도 정보 `LIMIT_MAXIMUM_UNKNOWN`은 기록에 남겼다. 연결된 모든 혜택이 실적 조건에서 제외됨을 확인했으며 임의 한도를 넣거나 적용 혜택의 계산 불가를 0원으로 바꾸지 않았다. 교통·택시 등은 합성 사실을 명시해 기존 계산기·실적 규칙으로 계산했다. 앱이 모든 사실을 자동으로 수집한다는 검증은 아니다.

이 결과는 **선정한 두 카드와 고정한 합성 생활비에서의 비교**다. YAMU가 모든 거래 경로·장기 합계에서 최적이라는 결론은 아니다. 수동 혜택표 선택은 이번 비교에 없으며, 사용자 시간·실수·실제 지급액도 측정하지 않았다. 기간뿐 아니라 거래 구성도 바뀌었으므로 EXP-001과의 차이를 기간 증가의 순수 효과로 해석하지 않는다.

## 코드와 재현 방법

기준 커밋은 `b26ebd944d47c5277260149c6096c67c70228596`이며 실행 소스·정책은 [압축본](runs/main-2026-11-13T08-12-30.835208800Z-001549c3-9328-424e-b65b-38762aadac1e/source-snapshot.zip)과 [해시](runs/main-2026-11-13T08-12-30.835208800Z-001549c3-9328-424e-b65b-38762aadac1e/manifest.json)에 있다. 실행 JDK는 21.0.12.1, 빌드는 저장소 Gradle 설정을 따랐다. Docker의 일회용 MySQL 8.4.11·Redis 7 컨테이너를 사용했다.

구현: [생성·상태·선택](../../../../be/src/test/java/com/yamu/be/recommendation/CardSelectionSixMonthSupport.java), [실행·사전 검증](../../../../be/src/test/java/com/yamu/be/recommendation/CardSelectionSixMonthTest.java), [설정](../../../../be/src/test/resources/recommendation/card-selection-exp-006.json). 최초 고정 거래와 새 생성값이 다르면 본 실행은 중단한다.

```powershell
# 저장소 be/에서. 일반 테스트는 사전 경계 검사를 포함하고 승인형 본 실험은 제외한다.
.\gradlew.bat clean test
python ..\infra\ci\check-test-results.py build\test-results\test

# 사전 경계 검사만 재실행할 때
.\gradlew.bat test --rerun-tasks --tests 'com.yamu.be.recommendation.CardSelectionSixMonthTest.preflightSixMonthBoundaries'

# 명시적으로 승인한 본 실험. 재실행은 새 고유 실행 폴더를 만든다.
$env:YAMU_EXP006_EXECUTE='APPROVED_6_MONTHS_V1'
try {
  .\gradlew.bat sixMonthExperiment
} finally { Remove-Item Env:YAMU_EXP006_EXECUTE }

# 저장소 루트에서. 재실행 결과를 검산할 때는 그 실행 폴더를 지정한다.
$run='docs/experiments/card-selection/exp-006-six-months/runs/main-2026-11-13T08-12-30.835208800Z-001549c3-9328-424e-b65b-38762aadac1e'
& docs/experiments/card-selection/exp-006-six-months/Verify-Run.ps1 -RunPath $run
& docs/experiments/card-selection/exp-006-six-months/Summarize-Run.ps1 -RunPath $run
& docs/experiments/card-selection/exp-006-six-months/Compare-Paths.ps1 -RunPath $run
& docs/experiments/card-selection/Verify-Archives.ps1
```

`test`·`check`·`build`는 승인 환경변수가 있어도 본 실험을 선택하지 않는다. 일반 CI의 실패·스킵 0건 검사는 그대로 유지한다. `sixMonthExperiment`는 승인값이 없거나 다르면 테스트 실행 전에 실패하며, 승인 조건은 IDE에서 직접 실행할 때도 적용된다. 이 태스크는 이전 실행 결과나 빌드 캐시로 성공을 대신하지 않는다.

일반 테스트 보고서는 `be/build/test-results/test`와 `be/build/reports/tests/test`, 본 실험 보고서는 `be/build/test-results/sixMonthExperiment`와 `be/build/reports/tests/sixMonthExperiment`에 각각 생성된다. Docker로 일회용 MySQL·Redis 컨테이너를 실행할 수 있어야 한다.

Windows JDK 17의 기본 인코딩이 MS949라면 한글 SQL을 읽는 기존 QA 시드 테스트가 실패할 수 있다. 일반 전체 테스트를 검증할 때는 실행 터미널에서 `$env:JAVA_TOOL_OPTIONS='-Dfile.encoding=UTF-8'`로 UTF-8을 지정한다. 이 설정은 본 실험 승인과 별개다.

실험 산출물은 `build/`가 아닌 이 문서 폴더에 저장된다. [검산 결과](runs/main-2026-11-13T08-12-30.835208800Z-001549c3-9328-424e-b65b-38762aadac1e/independent-verification.json)와 [실행 검증](runs/main-2026-11-13T08-12-30.835208800Z-001549c3-9328-424e-b65b-38762aadac1e/validation.json)도 함께 확인할 수 있다.
