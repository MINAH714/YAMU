# EXP-003 — 소비 규모에 따른 선택 효과

**3장 조건에서 YAMU는 10%·15%에서 업종 규칙보다 높았고, 25%·50%에서는 낮았으며, 75%에서는 같았다.** 두 카드 조건은 모든 배율에서 동률이었다. 결과를 보고 배율·카드·거래·업종 규칙을 변경하지 않았다.

## 결과가 달라진 이유

### 10%·15%: 모든 전략에서 월 한도 미소진

1,045회 중 해당 배율의 모든 전략·시드에서 관련 월 한도가 미소진임을 실제 사용량으로 확인했다. YAMU는 카페에서도 LOCA 60%를 선택하지만 업종 규칙은 톡톡 50%를 선택한다. 이 시점에는 LOCA 한도를 먼저 쓰는 데 따른 다음 거래의 손실이 없다. 카페 총액 3,800원/5,700원의 10% 차이가 각각 380원/570원이다.

15%에서 YAMU의 처음 사용은 1,438P/5,000P, 톡톡 스타벅스 0원/10,000원, LOCA 10,530원/13,000원이다. 업종 규칙은 처음 1,438P, 톡톡 2,850원, LOCA 7,110원이다. 이처럼 한도를 채우지 않아도 두 전략의 결과는 다를 수 있다.

### 25%: YAMU가 업종 규칙보다 1,713원 낮음

YAMU는 2·6·10·14번 스타벅스 거래에서 LOCA를 선택한다. 이 네 거래의 할인은 3,600원으로, 업종 규칙의 톡톡 3,000원보다 600원 크다. 그러나 같은 공유 한도를 먼저 사용해 17번 음식점에서는 1,150원만 남고, 21번 음식점에서는 LOCA를 쓰지 못한다.

업종 규칙은 음식점에 LOCA를 남겨 두므로 17번에서 1,950원, 21번에서 1,650원을 받는다. YAMU는 21번에서 처음으로 137P를 받는다. 차액은 `+600 −800 −1,650 +137 = −1,713원`이다.

| 카드 | 업종 규칙 | YAMU | 차이 |
|---|---:|---:|---:|
| 처음 | 2,398P | 2,535P | +137 |
| 톡톡 | 4,750원 | 1,750원 | −3,000 |
| LOCA | 11,850원 | 13,000원 | +1,150 |

업종 규칙은 어느 월 한도도 채우지 않았지만, LOCA 한도를 채운 YAMU보다 월 합계가 높다. **한도 사용률이 높다는 사실만으로 더 좋은 선택이라고 판단할 수 없다.**

### 50%: YAMU가 업종 규칙보다 2,075원 낮음

YAMU는 초기 카페에도 LOCA를 써서 9번 거래에 공유 한도를 소진한다. 업종 규칙은 음식점에만 사용해 13번에 소진한다. 두 전략의 LOCA 합계는 모두 13,000원이지만, YAMU는 초기 카페에서 활용할 수 있던 톡톡 혜택을 놓친다.

카드별 차이는 처음 `5,000−4,325=+675`, 톡톡 `6,750−9,500=−2,750`, LOCA 0으로 합계 −2,075원이다. 처음의 후반 추가 적립으로도 톡톡의 놓친 혜택을 만회하지 못했다.

### 75%와 두 카드 조건

75%에서는 두 전략 모두 처음 5,000P·톡톡 스타벅스 10,000원·LOCA 13,000원에 도달해 28,000원으로 같았다. 두 카드 조건에서는 모든 배율에서 고정 업종 규칙과 YAMU의 월 합계가 같았다. 개별 선택이 언제나 같다는 주장과 구분한다.

## 검증과 산출물

- JUnit 시나리오 1개 통과, 실패·오류·생략 0. 내부 본 비교 1,045회·62,760개 카드 평가에서 계산 불가 0건.
- 10개 조건 각각 초기·전체 소진·각 한도의 부분/완전 소진 검사. 2장 조건당 240개 상태×2장, 3장 조건당 288개 상태×3장, 합계 6,720개 사전 카드 평가. 가능한 모든 상태 공간을 탐색한 것은 아니다.
- 대표 음식점·스타벅스의 모든 카드 독립 수식 검산, 할인 적용 실적 제외, 일 한도 잔여 1P 및 다음 날짜 초기화 검증.
- 모든 실행의 한도 누적 사용량=차감량 합계 검증. 각 조건의 YAMU를 추가 재실행해 상태 격리·결정적 재현 확인. 이 10회 검증은 본 비교 횟수에서 제외.
- 각 조건 `summary.csv`: 전체 104/105회 결과와 소비 대비 혜택률. `random-statistics.json`·`random-distribution.csv`: 분포. `limit-utilization.csv`: 전략·시드·카드·한도·일/월별 사용률과 최초 소진 거래. 사용하지 않은 한도도 0으로 포함.
- 각 `raw-records.zip`: 거래별 전체 후보 평가·선택 인덱스·실적 및 한도 변화, 준비한 정책, 사전 평가. `raw-checksums.json`으로 압축 전후 동일성을 검증했다.
- 공통 `card-benefit-breakdown.csv`: 전략별 선택 카드의 혜택 합계. 선택하지 않은 카드는 이 파생표에 행이 없으며 사용률 표에서는 0으로 확인 가능.
- manifest에 기존 코드·정책·입력 해시, 실행 소스 ZIP에 새 테스트 두 파일과 고정 입력을 보존했다. 기존 EXP-001·002 원본과 미커밋 파일은 변경하지 않았고 색인·감사 문서만 승인 범위에서 덧붙였다.

## 해석의 한계

이번 결과는 동일 소비 구성의 금액 민감도 분석이다. 다섯 배율을 실제 소비자의 분포나 독립 사용자 표본으로 취급하지 않는다. 소비를 일괄 줄여 낮은 금액 거래를 만든 조건이므로 현실 소비의 대표성을 주장할 수 없다.

한도 미소진 구간의 우위는 거래 사이에 제약이 없을 때 즉시 최대 선택이 유리하다는 예상과 맞는다. 반면 25%·50%는 즉시 최대가 월 전체 최대를 보장하지 않는 반례다. 업종 규칙 또한 미래를 본 월간 최적해라고 주장하지 않는다.

전월 실적은 충분하지만 당월 소비는 낮게 설정했다. 다음 달의 실적·혜택 유지, 연회비·현금 지급·사용 편의성·실패 처리는 평가하지 않았다. 불리한 결과를 이유로 업종 규칙·배율·추천 알고리즘을 바꾸지 않았다. 추가 변경은 새 계획과 별도 실험으로 진행해야 한다.

## 재현

`be`에서 다음 명령을 실행한다. 기존 실험 테스트를 직접 재실행할 필요가 없다.

```powershell
.\gradlew.bat test --tests com.yamu.be.recommendation.CardSelectionConsumptionScaleTest --rerun-tasks
```

새 `executions/exp003-UTC-UUID/`에 기록한다. Docker가 없어 skipped면 성공 실험으로 세지 않는다. 원본과 기존 실행을 덮어쓰지 않는다. 보존용 압축·검증 명령은 [전체 색인](../README.md#재현)을 따른다.

별도 checkout 복원은 EXP-001 source-overlay.zip, EXP-002 execution-source.zip의 확장 입력 및 EXP-003 execution-source.zip을 사용한다. 현재 환경의 실행은 확인했지만 별도 머신의 clean 복원 실행은 미실시다. 커밋·push는 수행하지 않았다.
