# 야무(YAMU) 요구사항 명세서

> 결제는 간편하게, 혜택은 야무지게.

## 1. 문서 개요

- **프로젝트명:** 야무(YAMU)
- **문서명:** 요구사항 명세서
- **목적:** 카드 추천, 모의 결제, 카드 실적 관리, 잔액 예보 및 알림 기능의 요구사항을 정의한다.
- **서비스 전제:** MVP에서는 실제 결제를 지원하지 않으며, 모의 결제 환경을 사용한다.

## 2. 기능 요구사항

### 2.1 사용자 및 카드 관리

| ID | 요구사항 | 설명 |
|---|---|---|
| FR-001 | 사용자별 데이터 분리 | 사용자의 카드, 계좌, 거래, 혜택, 실적 및 알림 데이터를 사용자별로 분리한다. |
| FR-002 | 보유 카드 등록 | 사용자가 보유 카드를 등록할 수 있다. |
| FR-003 | 등록 카드 목록 조회 | 등록된 카드 목록을 조회할 수 있다. |
| FR-004 | 등록 카드 수정·해제 | 카드 정보를 수정하거나 등록을 해제할 수 있다. |
| FR-005 | 카드별 혜택 조건 조회 | 카드별 혜택, 실적 조건, 할인 및 적립 한도를 조회할 수 있다. |
| FR-006 | 체크카드 계좌 연결 정보 관리 | 체크카드와 연결된 계좌 정보를 관리할 수 있다. |

### 2.2 카드 추천 및 모의 결제

| ID | 요구사항 | 설명 |
|---|---|---|
| FR-007 | 통합 바코드 표시 | 서비스 내 통합 바코드를 표시한다. |
| FR-008 | 가맹점 정보 수신 | 결제 추천에 필요한 가맹점 및 업종 정보를 수신한다. |
| FR-009 | 결제 요청 금액 수신 | 결제 요청 금액을 수신한다. |
| FR-010 | 바코드와 결제 요청 연결 | 바코드와 해당 결제 요청을 연결한다. |
| FR-011 | 결제 가능 카드 필터링 | 결제 조건을 충족하는 등록 카드를 선별한다. |
| FR-012 | 전월 실적 조건 판정 | 카드별 전월 실적 충족 여부를 판정한다. |
| FR-013 | 가맹점 업종·혜택 매칭 | 가맹점 업종과 카드 혜택 조건을 매칭한다. |
| FR-014 | 할인·캐시백·적립액 계산 | 적용 가능한 할인, 캐시백 및 포인트 적립액을 계산한다. |
| FR-015 | 혜택 조건 및 할인 한도 반영 | 최소 결제 금액, 적용 제외 조건 및 잔여 한도를 계산에 반영한다. |
| FR-016 | 카드별 순혜택 비교 | 동일 결제에 대한 카드별 예상 혜택을 비교한다. |
| FR-017 | 최적 카드 추천 이유 제공 | 추천 카드와 추천 근거 및 예상 혜택을 제공한다. |
| FR-018 | 추천 불가능 상황 안내 | 추천 가능한 카드가 없거나 데이터가 부족한 경우 사유를 안내한다. |
| FR-019 | 추천 카드로 모의 승인 요청 | 선택한 추천 카드로 모의 승인 요청을 수행한다. |
| FR-020 | 모의 승인 실패 처리 | 모의 승인 실패 상태와 사유를 처리한다. |
| FR-021 | 중복 승인 방지 | 동일 결제 요청이 중복 처리되지 않도록 방지한다. |
| FR-022 | 결제 상태 관리 | 결제 요청의 처리 상태를 관리한다. |
| FR-023 | 거래 및 혜택 기록 | 결제 결과와 해당 거래의 혜택 정보를 기록한다. |
| FR-024 | 실제 혜택 입력·조회 | 사용자가 확인한 실제 혜택 금액을 입력하고 조회할 수 있다. |
| FR-025 | 결제 실패 복구 및 재시도 제어 | 결제 실패 시 재시도 가능 여부와 횟수 및 상태를 관리한다. |
| FR-026 | 월별 결제 내역 조회 | 월별 결제 내역을 조회할 수 있다. |

### 2.3 카드 실적 및 혜택 관리

| ID | 요구사항 | 설명 |
|---|---|---|
| FR-027 | 월별 실적 인정 거래 집계 | 카드별·월별 실적 인정 거래를 집계한다. |
| FR-028 | 실적 제외 항목 반영 | 카드 약관에 따른 실적 제외 거래를 집계에서 제외한다. |
| FR-029 | 달성률·부족액 표시 | 실적 달성률과 남은 실적 금액을 표시한다. |
| FR-030 | 다음 달 혜택 영향 안내 | 현재 실적 달성 여부가 다음 달 혜택에 미치는 영향을 안내한다. |
| FR-031 | 월말 실적 미달 사전 알림 | 월말 실적 미달 가능성이 있는 경우 사전 알림을 제공한다. |
| FR-032 | 실적 달성 가능성 추정 | 예정 지출과 소비 패턴을 바탕으로 실적 달성 가능성을 추정한다. |
| FR-033 | 과소비 방지 소비 가이드 | 추가 소비에 따른 혜택과 지출 부담을 비교해 불필요한 소비를 경고한다. |

| FR-044 | 잔액 부족 사전 알림 | 잔액 부족이 예상되는 시점 전에 알림을 제공한다. |

| FR-046 | 소비 패턴 기반 예측 개선 | 누적 소비 패턴을 활용해 생활비 및 잔액 예측을 개선한다. |

| ID | 요구사항 | 설명 |

## 4. 서비스 정책 및 제약사항

| ID | 정책 | 내용 |
|---|---|---|
| POL-001 | 실물 카드 약관 정확성 제약 | 혜택 계산 정확도는 확보한 카드 약관 및 혜택 데이터의 정확성에 영향을 받는다. |
| POL-002 | 실제 결제 미지원 | MVP에서는 실제 승인·매입을 수행하지 않으며 모의 결제 결과는 실제 금융 거래가 아니다. |
| POL-003 | 계산과 AI 설명의 분리 | 혜택·실적·잔액은 규칙 기반 로직으로 계산하고 AI는 결과 설명 및 요약에 활용한다. |
| POL-004 | 예측값의 명확한 표시 | 잔액 및 소비 예측은 추정치임을 표시하고 확정 데이터와 구분한다. |

## 5. 확인 필요 사항

개발 착수 전 팀 내 합의가 필요한 항목이다.

- [ ] 인증 및 계정 관리 방식 결정
- [ ] 카드·계좌 데이터 획득 방식 결정
- [ ] 바코드·POS 인터페이스 결정
- [ ] 동률 및 장기혜택 우선순위 정책 결정
- [ ] 혜택 평가 기준 정의
- [ ] 취소·환불·부분취소 범위 확정
- [ ] 실적 반영 시점 및 예외 규칙 결정
- [ ] 예측 기준 및 중복계산 정책 결정
- [ ] 실결제 연결 가능성 검토
- [ ] 응답 성능·가용성 목표 설정
- [ ] 성과 지표 정의 및 측정방법 결정

## 6. 권장 구현 원칙

1. **계산 로직과 AI 설명 분리:** 혜택 금액, 실적 및 잔액은 검증 가능한 로직으로 계산한다.
2. **사용자 데이터 격리:** 사용자 소유 데이터를 조회·수정할 때마다 권한을 검증한다.
3. **중복 요청 방지:** 결제 요청에 멱등성을 적용해 중복 실행과 중복 거래 기록을 방지한다.
4. **확정값과 예측값 구분:** 화면과 API에서 확정 데이터 및 예측 데이터를 명시적으로 구분한다.
5. **데이터 기준 시점 관리:** 카드 혜택 규칙과 예측에 사용한 데이터의 출처 및 기준일을 추적한다.
6. **미확정 정책 분리:** 합의 전인 우선순위와 예외 규칙은 코드에 고정하지 않고 설정 또는 별도 정책 모듈로 관리한다.

## 7. MVP 구현 범위 제안

### 필수 구현

- 사용자별 데이터 분리
- 샘플 카드 등록 및 혜택 규칙 관리
- 가맹점·금액 기반 카드 추천 및 추천 사유
- 전월 실적 및 할인 한도 계산
- 모의 결제 성공·실패·중복 요청 처리
- 월별 거래 및 혜택 내역 조회
- 실적 달성률·부족액 및 과소비 방지 가이드
- 기본 잔액 예보 및 예측값 표시
- 알림 목록 및 중복 알림 억제

### 후속 구현 검토

- 외부 금융 데이터 연동
- 실제 카드·계좌 데이터 자동 수집
- 실제 결제 연동
- 개인별 소비 예측 고도화
- 고급 알림 설정 및 장기 혜택 최적화

## 8. 요구사항 변경 관리

- 요구사항 변경 시 관련 ID, 변경 내용, 변경 사유 및 영향 범위를 기록한다.
- 구현 여부와 테스트 케이스를 요구사항 ID와 연결해 추적한다.
- 확인 필요 사항은 담당자, 결정일 및 결정 내용을 별도로 기록한다.
