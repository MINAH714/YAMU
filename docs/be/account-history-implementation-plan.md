# 계좌 입출금 저장 구현 계획 — S15P31E103-517

기준: origin/develop 5cc5b6cc. 승인된 설계와 QA 초기화·실제 경계 연결 요구를 구현한다.

## 변경 대상

- 새 Flyway: 실제/합성 stream, 외부 거래 원장, 동기화 실행 및 시작 잔액 근거를 포함한 조회 완료 범위(4개 테이블).
- 새 계좌 이력 도메인: 소유권 검증, DB 읽기, 외부 조회 후 짧은 저장 트랜잭션, 동시 실행 세대 검증.
- assetflow: 과거 DB 조회, 기존 현재 잔액/예보 유지. 합성은 SIMULATED, actualBalance=null로 표시.
- seed/qa: 기존 소비 시드와 독립적인 자산 이력 plan/apply/verify/reset/purge 및 전체 정리 종속성.
- Android: 합성 출처와 경계 표시. 기존 일반 사용자 계약 유지.
- 스키마 사전, API 계약, 인프라 실행·검증·롤백 안내.

## 구현 기준

외부 호출 중 DB 트랜잭션을 유지하지 않는다. UNIQUE와 실행 세대 재검사로 중복과 늦은 결과를 막는다. 원본 충돌·누락은 덮어쓰지 않으며 외부 실패는 0건 조회가 아니다. 무거래 구간은 완전 조회와 검증된 시작 잔액을 모두 요구한다. 일별 결과는 초기 구현에서 원장·조회 범위로 재계산하며 별도 캐시 테이블은 필요성이 확인될 때 추가한다.

QA 실제 경계는 실제 최초 거래 이전의 검증된 잔액으로 고정한다. 현재 잔액을 소급하지 않는다. 0원 경계에서 합성 중간 잔액이 음수가 되면 적재를 거절하고 입력 시나리오를 수정해야 한다. 초기 금융망 입금을 삭제하거나 경계를 임의 이동하지 않는다. 기존 소비·가입·기기·PIN·계좌 연결·실제 이력은 자산 전용 초기화에서 보존한다.

## 검증 계획

격리 MySqlTestSupport로 FK/UNIQUE/소유권, 재실행·동시 실행, 충돌·누락·무거래·동일 초 순서 불명·잔액 불일치, 외부 실패, 합성 경계, 초기화 후 기존 데이터 보존을 검증한다. 기존 자산 흐름·예보와 Android 변환 테스트를 회귀 확인한다.

실제 RDS 마이그레이션·금융 거래·push·MR 승인/merge는 수행하지 않는다. 인프라 전달 시 실제 경계 근거 확보 및 적재 검증을 별도 실행 단계로 남긴다.

## 현재 진행

전용 worktree와 Jira 517 진행 중 상태 준비 완료. 저장·동기화·DB 자산 흐름·QA 전용 CLI·Android 합성 표시 구현 후 검증 중이다. 실제 환경 적재는 수행하지 않았다. 전체 사용자 초기화의 실제 이력 삭제 확장은 자동 승인 검토에서 거절되어, 이력이 있으면 전체 초기화를 사전에 거절하도록 구현했다.

사용자 승인에 따라 별도 앵커 테이블을 제외했다. 시작 잔액·근거는 coverage에 통합하고 종료 잔액은 재계산한다. 일별 캐시 테이블도 추가하지 않는다.
