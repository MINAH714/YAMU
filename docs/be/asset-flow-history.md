# 과거 잔고 조회 기반 (S15P31E103-487)

## 변경 범위

`SsafyTransferApi.historySnapshot`은 조회 기간·방향·보고 건수·받은 거래·수신 완료 시각을 `BankHistory`로 반환한다. 기존 history와 태그 기반 결제/취소 복구 동작은 변경하지 않는다. 엄격한 count 일치·거래 ID 중복·기간·방향 검사는 새 경로에만 적용한다.

`DailyBalanceReconstructor`는 소유권을 확인한 계좌의 완전한 전체 입출금 자료를 받아 한국 날짜 일말 잔고를 구성하는 순수 계산기다. 현재 잔고·오늘 일말·미래 예측을 연결하거나 금융망을 호출하지 않는다. DB 스키마 변경과 공개 API 추가는 없다.

## 검증과 한계

- 조회 시작일 직전의 확인된 잔고가 없으면 첫 거래의 거래 후 잔고와 입출금액에서 역산한다. 이후 모든 거래의 금액·잔고 연결을 확인한다.
- 완전한 무거래 목록에 기준 잔고도 없으면 실제 0원이 아니라 NO_ANCHOR다.
- count 누락·불일치·중복 거래·범위 오류는 HISTORY_INCOMPLETE다. 같은 초 거래는 번호 순서를 추정하지 않고 AMBIGUOUS_ORDER다.
- 거래가 없는 날은 완전성이 확인된 기간에서만 직전 잔고를 유지한다. 한 건이라도 잔고 연결이 불일치하면 전체 조회 구간을 미확인으로 둔다.
- 금융망 totalCount와 받은 목록이 같다는 것은 공급자 계약 기준의 완전성이다. 공급자 자체의 잘못된 totalCount까지 증명하지 않는다.
- queriedAt은 은행 스냅샷 시각이 아니라 조회 수신 시각이다. 오늘 현재 잔고 캐시를 과거 시작 잔고로 사용하면 안 된다.
- 일별 분할 재조회·소유권을 검증하는 orchestration·다계좌 합산·월별 공개 API·현재/예측 연결은 S15P31E103-488에서 구현한다. 현재 첫 태스크 결과만으로 운영 그래프를 제공하지 않는다.
- 같은 시각 거래가 많은 계좌는 이 단계에서 표시할 수 없다. 순서 근거가 확보될 때까지 임의 정렬하지 않는다.
- 새 금액 계산은 호출 지역 변수로만 처리한다. 쓰기·출금·차감·자동 재시도는 없다.

## 검사

Java 17로 be 폴더에서 실행한다.

```powershell
.\gradlew.bat test --tests '*SsafyTransferApiTest' --tests '*DailyBalanceReconstructorTest'
```

금융망 응답은 테스트 서버로 대체한다. 실제 계좌나 DB는 호출하지 않는다. 외부 타임아웃/출금 결과 불명은 기존 SsafyTransferApiTest가 함께 검증한다.
