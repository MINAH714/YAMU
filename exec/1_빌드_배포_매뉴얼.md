# 1. 빌드 · 배포 매뉴얼

GitLab에서 저장소를 클론한 뒤 YAMU를 빌드하고 배포하는 방법을 정리했습니다.
자세한 절차는 각 절에 링크한 저장소 문서에 있고, 이 문서는 그 요약과 순서입니다.

- 저장소: `https://lab.ssafy.com/s15-final/S15P31E103.git` (배포 브랜치 `master`, 통합 브랜치 `develop`)
- 서비스 주소: `https://yamu.it.kr` (POS 웹 `/`, API `/api/`)
- 비밀번호·키 같은 **비밀값은 이 문서와 저장소에 적지 않습니다.** 변수 이름과 그 값을 넣는 파일만 적습니다. 값은 팀에 따로 요청합니다.

## 구성 한눈에 보기

| 구성 요소 | 폴더 | 실행 형태 |
|---|---|---|
| API 서버 | `be/` | Docker 컨테이너(Spring Boot JAR), EC2 |
| 사용자 앱 · 모의 POS 앱 | `fe/android/` | Android APK (`customer` · `pos` 두 flavor) |
| 모의 POS 웹 | `fe/pos/` | 정적 파일, EC2 Nginx가 제공 |
| AI 예측 서비스 | `ai/` | Docker 컨테이너(FastAPI), BE와 같은 내부 네트워크 |
| DB | — | AWS RDS MySQL 8.4.11 |
| 캐시 | — | Redis 7 컨테이너 |
| CI/CD | `Jenkinsfile`, `Jenkinsfile.cd`, `infra/` | EC2의 Jenkins(Tailscale 전용) |

```
브라우저(POS 웹) ─┐
Android 앱 ───────┼─ HTTPS ─▶ Nginx(EC2) ─┬─ /        → /var/www/yamu-pos (POS 정적 파일)
                  │                       └─ /api/    → 127.0.0.1:8080 (BE 컨테이너)
                  │                                        ├─ Redis 컨테이너 (내부 네트워크)
                  │                                        ├─ AI 컨테이너 :8001 (내부 네트워크)
                  │                                        ├─ AWS RDS MySQL (TLS)
                  │                                        └─ SSAFY 금융망 API (HTTPS)
```

`fe/mobile/`(Expo)은 초기 골격만 있는 폴더로, 배포하지 않습니다. 실제 사용자 앱은 `fe/android/`입니다.

### 꼭 알아야 할 설정

- **시간대는 UTC로 통일합니다.** JVM(`-Duser.timezone=UTC`), JSON(`spring.jackson.time-zone`), JDBC(`serverTimezone=UTC`) 모두 UTC입니다. 실적 월·청구일처럼 한국 날짜 기준인 계산만 코드에서 `Asia/Seoul`을 씁니다. (`docs/be/local-setup.md` 「시간대」)
- **DB 스키마는 Flyway가 서버 기동 시 만듭니다.** `be/src/main/resources/db/migration/*.sql`, `ddl-auto: validate`, `out-of-order: true`. 빈 DB로 서버를 켜면 테이블이 생기고, 덤프를 넣은 DB로 켜면 남은 마이그레이션만 적용됩니다. (`docs/be/jpa-flyway.md`)
- 운영에서는 Swagger를 끄고(`SPRINGDOC_*=false`), actuator는 `health`만 열고 세부 정보는 숨깁니다. Nginx는 `/actuator/`를 프록시하지 않습니다.

## 2) 빌드할 때 쓰는 환경 변수

`필수`가 아닌 값은 비워도 서버가 뜹니다. "비밀"은 값을 팀에 따로 받습니다.

### BE (운영 컨테이너 환경 변수)

| 변수 | 뜻 | 필수 | 값 |
|---|---|---|---|
| `SPRING_PROFILES_ACTIVE` | 프로필. 운영 `prod`, 로컬 기본 `local` | 필수 | `prod` |
| `SERVER_PORT` | API 포트 | 선택 | `8080` |
| `SPRING_DATASOURCE_URL` | JDBC 주소. RDS는 `sslMode=VERIFY_IDENTITY` + truststore | 필수 | `infra/compose.rds.yml`이 조립 |
| `SPRING_DATASOURCE_USERNAME` · `SPRING_DATASOURCE_PASSWORD` | DB 계정 | 필수 | 비밀 |
| `SPRING_DATA_REDIS_HOST` · `SPRING_DATA_REDIS_PORT` | Redis 주소 | 필수 | `redis` · `6379` |
| `YAMU_CRYPTO_DATA_KEY_1` | 개인정보(전화번호·계좌·카드번호) 암호화 키, Base64 32바이트 | 필수 | 비밀 |
| `YAMU_CRYPTO_HMAC_KEY` | 검색용 해시 키, Base64 32바이트 | 필수 | 비밀 |
| `YAMU_CRYPTO_PIN_PEPPER` | 간편 비밀번호 해시 pepper, Base64 32바이트 | 필수 | 비밀 |
| `YAMU_CRYPTO_DATA_KEY_ID` | 지금 쓰는 데이터 키 번호 | 선택 | `1` |
| `YAMU_JWT_SECRET` | 로그인 토큰 서명 키, Base64 32바이트 이상 | 필수 | 비밀 |
| `SSAFY_API_KEY` | SSAFY 금융망 API 키 | 사실상 필수 (없으면 계좌·결제 실패) | 비밀 |
| `YAMU_POS_KEY` | 모의 POS가 보내는 `X-POS-Key` | POS 사용 시 필수 | 비밀 |
| `YAMU_ADMIN_KEY` | 운영 관리 API `X-Admin-Key` (비우면 403) | 선택 | 비밀 |
| `AI_BASE_URL` | AI 서비스 주소. 비우면 AI 없이 단순 계산(TSB)으로 예보 | 선택 | `http://ai:8001` |
| `DATA_GO_KR_SERVICE_KEY` | 공휴일 API 키(디코딩 키). 비우면 내장 공휴일 파일 사용 | 선택 | 비밀 |
| `PAYMENT_RECOVERY_ENABLED` | 결과 불명 결제 복구 작업 | 선택 | 운영 `true` |
| `BILLING_JOBS_ENABLED` | 청구서 생성·카드값 출금 작업 | 선택 | 운영 `true` |
| `NOTIFICATION_JOBS_ENABLED` | 예약 알림 작업 | 선택 | 운영 `true` |
| `YAMU_CARD_IMAGE_BASE_URL` | 카드 이미지 CDN 주소 | 선택 | 기본값 있음 |

- 세 암호화 키는 서로 달라야 하고, 비어 있으면 서버가 뜨지 않습니다(`application.yml` `yamu.crypto`).
- 정의: `be/src/main/resources/application.yml`, `infra/compose.prod.yml`, `infra/compose.rds.yml`.

### Compose가 읽는 서버 env 파일

| 파일(서버, 커밋 안 함) | 견본(커밋됨) | 변수 |
|---|---|---|
| `infra/.env.prod` | `infra/.env.prod.example` | `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `DB_ROOT_PASSWORD`, `YAMU_CRYPTO_DATA_KEY_1`, `YAMU_CRYPTO_HMAC_KEY`, `YAMU_CRYPTO_PIN_PEPPER`, `YAMU_JWT_SECRET`, `DATA_GO_KR_SERVICE_KEY`, `PAYMENT_RECOVERY_ENABLED`, `APP_VERSION` |
| `infra/.env.rds` | `infra/.env.rds.example` | `RDS_HOST`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `RDS_TRUSTSTORE_PATH`, `APP_VERSION` |
| `infra/.env.jenkins` | `infra/.env.jenkins.example` | `JENKINS_BIND_IP` |
| `infra/.env.ci-agent` | `infra/.env.ci-agent.example` | `JENKINS_AGENT_SECRET`, `JENKINS_URL` |

`SSAFY_API_KEY`, `YAMU_POS_KEY`, `YAMU_ADMIN_KEY`, `AI_BASE_URL`, `BILLING_JOBS_ENABLED`, `NOTIFICATION_JOBS_ENABLED`는 위 파일이 아니라 서버 전용 override 파일(`/etc/yamu-cd/active-image.json`)의 backend `env_file`로 넣습니다(`docs/infra/jenkins-cd.md`).

### BE 로컬

- `be/src/main/resources/application-local.yml.example`을 `application-local.yml`로 복사합니다. 이 파일이 `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `REDIS_PORT`와 `yamu.crypto.*`, `yamu.jwt.secret`, `yamu.fin-api.api-key`, `yamu.pos.key`, `yamu.admin.key`, `yamu.holiday.service-key`를 정합니다.
- 로컬 MySQL·Redis는 `be/docker-compose.yml`(계정 `yamu`, 로컬 전용 비밀번호가 커밋돼 있음)로 띄웁니다.

### POS 웹 (빌드할 때 번들에 들어가는 값)

`fe/pos/.env.example`을 `fe/pos/.env.local`(또는 `.env.production.local`)로 복사해 채웁니다. 이 값은 **빌드 결과 JS에 그대로 들어가므로** 바꾸면 다시 빌드해야 합니다.

| 변수 | 뜻 |
|---|---|
| `VITE_API_BASE_URL` | API 경로. 운영 `/api` |
| `VITE_POS_KEY` | BE `YAMU_POS_KEY`와 같은 값. 모의 POS 전용 키만 씁니다 |
| `VITE_STARBUCKS_POS_CODE` · `VITE_GS25_POS_CODE` | 매장 단말 코드 (`POS-STARBUCKS-GENERAL`, `POS-GS25-GENERAL`) |
| `VITE_STARBUCKS_MERCHANT_ID` · `VITE_GS25_MERCHANT_ID` | 그 브랜드의 `merchant.merchant_id` (운영 DB 기준 스타벅스 1, GS25 2) |
| `VITE_POS_MOCK_RESULT` | `true`면 결제 결과 조회를 화면 안 가짜로 대신(BE 없이 화면만 볼 때) |

CI(`Jenkinsfile`)는 `VITE_API_BASE_URL`만 넣으므로, CI가 보관한 `dist`에는 POS 키가 없습니다. 운영 POS는 키를 넣고 직접 빌드합니다.

### Android (`fe/android/local.properties`, 커밋 안 함)

| 키 | 뜻 |
|---|---|
| `sdk.dir` | Android SDK 경로 |
| `yamu.baseUrl` | debug 빌드의 API 주소. 에뮬레이터 → 내 PC BE는 `http://10.0.2.2:8080/api/` |
| `yamu.posKey` | POS 앱이 보내는 `X-POS-Key` |
| `yamu.releaseBaseUrl` | release 빌드 API 주소. `https://`로 시작하고 `/api/`로 끝나야 함 (운영 `https://yamu.it.kr/api/`) |
| `yamu.release.storeFile` · `storePassword` · `keyAlias` · `keyPassword` | release 서명 키 (비밀) |

Gradle 속성으로도 넘길 수 있습니다: `-Pyamu.releaseBaseUrl=...`.

### AI (`ai/.env.example`)

`AI_PORT`(8001), `AI_LIVING_COST_MODEL_DIR`, `AI_CREDIT_SPENDING_MODEL_DIR`, `AI_DOCS_ENABLED`(운영은 끔). 앱은 `.env`를 자동으로 읽지 않으므로 실행 환경 변수로 넣습니다.

## 3) 빌드 · 배포 순서와 특이사항

### 로컬에서 실행해 보기

```powershell
# BE (be 폴더)
Copy-Item src\main\resources\application-local.yml.example src\main\resources\application-local.yml
docker compose up -d                 # MySQL 8.4.11 + Redis 7
.\gradlew.bat bootRun                # http://localhost:8080/actuator/health
.\gradlew.bat test                   # Docker가 켜져 있으면 Testcontainers DB 테스트까지

# 카탈로그·테스트 사용자 시드 (be 폴더, 처음 한 번)
.\seed\load.ps1                      # 같은 PowerShell 창에서 bootRun 해야 생성된 키를 씀

# POS 웹 (fe/pos)
npm ci; npm run lint; npm run build; npm run dev   # http://localhost:5173, /api는 localhost:8080으로 프록시

# Android (fe/android)
.\gradlew.bat assembleCustomerDebug assemblePosDebug

# AI (ai)
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m app.main             # http://localhost:8001/health
```

BE가 로컬 AI를 쓰게 하려면 BE를 켤 때 `AI_BASE_URL=http://localhost:8001`을 넣습니다.

### 운영 배포 — BE (Jenkins CD)

1. `master`에 Merge되면 `yamu/cd` Job(`Jenkinsfile.cd`)이 5분 폴링으로 시작합니다.
2. `yamu/ci-master`로 전체 CI(`clean test bootJar`, POS lint·build)를 돌립니다. 테스트 0개·실패·skip이 있으면 멈춥니다.
3. Mattermost로 승인 요청을 보내고 Jenkins 사용자 `yamu`의 승인을 30분 기다립니다.
4. 승인되면 SSH(자격증명 `yamu-cd-trigger`)로 서버의 `/usr/local/sbin/yamu-cd`(= `infra/cd/deploy.py`)에 빌드 번호만 넘깁니다.
5. 서버 스크립트가 아래를 확인한 뒤 교체합니다.
   - CI 결과 SUCCESS, 매니페스트 SHA-256과 `master` 커밋 일치
   - Flyway 마이그레이션 파일이 기존 JAR과 다르면 **배포 거부**(DB 변경은 사람이 확인하고 배포)
   - 비밀 환경 변수(`SSAFY_API_KEY`, `YAMU_POS_KEY`, `YAMU_JWT_SECRET`, `YAMU_CRYPTO_*` 등)가 배포 전후로 같은지
6. `docker compose up --no-deps --no-build --pull never --wait backend` 후 `/actuator/health`가 `UP`, `https://yamu.it.kr/api/health`가 `ok`인지 봅니다. 실패하면 **이전 이미지로 자동 롤백**합니다(DB는 되돌리지 않음).

자세한 설치·권한 설정: `docs/infra/jenkins-cd.md`, `docs/infra/jenkins-ci.md`, `docs/infra/jenkins.md`.

### 운영 배포 — BE 수동

```bash
# 서버 저장소 루트. 값은 출력하지 않도록 config는 --quiet로만 확인
sudo docker compose --env-file infra/.env.prod --env-file infra/.env.rds \
  -f infra/compose.prod.yml -f infra/compose.rds.yml config --quiet
sudo docker compose --env-file infra/.env.prod --env-file infra/.env.rds \
  -f infra/compose.prod.yml -f infra/compose.rds.yml build backend
sudo docker compose --env-file infra/.env.prod --env-file infra/.env.rds \
  -f infra/compose.prod.yml -f infra/compose.rds.yml up -d --wait --wait-timeout 300 backend
curl --fail https://yamu.it.kr/api/health
```

- `compose.prod.yml`의 `mysql` 서비스는 RDS 전환 전 구성이라 지금은 쓰지 않습니다(`legacy-db` 프로필, 중지).
- RDS 접속용 truststore는 `infra/rds/prepare-truststore.sh`로 만듭니다(`/opt/yamu/certs/rds-truststore.p12`). (`docs/infra/rds.md`)
- Docker 빌드 단계에는 Docker 소켓이 없어 Testcontainers DB 테스트가 건너뛰어집니다. DB 테스트는 CI에서 확인합니다.

### 운영 배포 — POS 웹 (수동)

```powershell
# Windows, 저장소 루트. fe/pos/.env.production.local에 VITE_POS_KEY 등 운영 값을 먼저 넣는다
Set-Location fe/pos
npm ci; npm run lint
$env:VITE_API_BASE_URL = '/api'
npm run build
scp -r .\dist ec2:~/deploy/pos-upload/
```

서버에서 `~/deploy/pos-upload/dist`를 `/var/www/yamu-pos`로 복사하고 소유자 `root:www-data`, 권한 755/644로 맞춥니다. 자동 롤백은 없으니 기존 폴더를 백업해 둡니다. (`docs/infra/pos-deployment.md`)

- POS는 BE와 **같은 출처**(`https://yamu.it.kr`)에서 열어야 합니다. BE에 CORS 설정이 없습니다.
- 카메라(QR 스캔)는 HTTPS에서만 켜집니다. HTTP로 열면 결제 코드 16자리를 직접 입력합니다.
- 화면 기준은 가로 1333×800(Galaxy Tab S6 Lite)입니다.

### 운영 배포 — AI

```bash
docker build -t yamu-ai:<커밋> ai      # Dockerfile 안에서 단위 테스트를 통과해야 이미지가 만들어짐
```

- 호스트 포트를 열지 않고 BE와 같은 내부 네트워크에만 붙입니다. BE에는 `AI_BASE_URL=http://ai:8001`.
- 운영 AI 컨테이너(`yamu-prod-ai-1`) 정의는 저장소의 compose가 아니라 서버 전용 override 파일(`/etc/yamu-cd/active-image.json`)에 있습니다. Jenkins CD는 AI를 빌드·교체하지 않습니다.
- AI가 멈추거나 1초 안에 답하지 않으면 BE는 30초 동안 AI를 부르지 않고 단순 계산(TSB)으로 예보를 냅니다.
- 학습된 모델 파일 6개(`ai/models/living-cost/`, `ai/models/credit-spending/` 의 `h7·h14·h30.joblib`)는 저장소에 들어 있고, 서버가 읽을 때 SHA-256을 확인합니다. (`ai/README.md`, `ai/models/README.md`)

### 운영 배포 — Android APK

```powershell
# fe/android. 운영 서버에 붙는 release APK
.\gradlew.bat assembleCustomerRelease -Pyamu.releaseBaseUrl=https://yamu.it.kr/api/
.\gradlew.bat assemblePosRelease      -Pyamu.releaseBaseUrl=https://yamu.it.kr/api/
```

- 서명 키는 `local.properties`의 `yamu.release.*`로 넣습니다. 키 파일(`*.jks`)은 커밋하지 않습니다.
- Jenkins `yamu/mobile/apk-mock` Job은 가짜 데이터용 `customerDebug`만 만들어 비공개 S3에 올리고 24시간 다운로드 링크를 줍니다. 운영 연동 release APK는 위 명령으로 직접 만듭니다. (`infra/android/README.md`)
- debug 빌드가 HTTP로 붙을 수 있는 곳은 `localhost`, `10.0.2.2`뿐입니다.

### 그 밖의 특이사항

- **암호화 키를 바꾸거나 잃으면 저장된 전화번호·계좌번호·카드번호를 읽을 수 없습니다.** `YAMU_CRYPTO_HMAC_KEY`, `YAMU_CRYPTO_PIN_PEPPER`는 바꾸지 않습니다. 데이터 키를 바꿀 때는 새 번호(`YAMU_CRYPTO_DATA_KEY_2`)를 추가하고 `YAMU_CRYPTO_DATA_KEY_ID`만 올립니다. (`docs/be/personal-data-crypto.md`)
- **3번 DB 덤프를 다른 서버에 넣으면** 같은 암호화 키를 써야 암호문 칸을 읽을 수 있습니다. 키가 다르면 서버는 뜨지만 그 칸을 읽는 기능(로그인 전화번호 확인, 계좌·결제)이 실패합니다.
- `docker compose down -v`는 Redis 볼륨을 지우므로 운영에서 쓰지 않습니다.
- 시연·QA 데이터는 서버 시작 때 자동으로 넣지 않습니다. 필요할 때 명시적으로 실행합니다(`be/seed/README.md`, `be/seed/qa/README.md`, `be/seed/yoonseo/README.md`, `docs/infra/jenkins-cd.md` 「페르소나」).
- 본인 확인 문자는 외부 업체 없이 모의로 처리합니다. 인증번호를 문자 대신 응답의 `demoCode`로 돌려줍니다(`application.yml`의 `yamu.auth.signup.expose-demo-code: true`). 문자 서비스를 붙이면 `false`로 바꿉니다.

|---|---|
| `be/src/main/resources/application.yml` | BE 공통 설정. 모든 비밀값은 `${환경변수}`로만 받음 |
| `be/src/main/resources/application-local.yml.example` | 로컬 BE 설정 견본 (DB·Redis·암호화 키·금융망 키·POS 키 자리) |

| `be/src/test/resources/application-test.yml` | 테스트 전용 키 (운영과 무관) |
| `be/docker-compose.yml` | 로컬 MySQL·Redis (로컬 전용 계정 `yamu`/`yamu_local`, root `root_local`) |
| `be/.env.example` | 로컬 포트·DB 계정 덮어쓰기 견본 |
| `be/seed/.env.seed.example`, `be/seed/persona.example.json` | 시드용 금융망 회원·계좌 자리 |
| `infra/compose.prod.yml`, `infra/compose.rds.yml` | 운영 컨테이너 구성과 넣는 환경 변수 이름 |
| `infra/.env.prod.example`, `infra/.env.rds.example` | 운영 DB 계정·암호화 키·JWT 키 자리 |
| `infra/.env.dev.example`, `infra/.env.jenkins.example`, `infra/.env.ci-agent.example` | 개발 서버·Jenkins·CI 에이전트 자리 |
| `infra/cd/config.example.json` | CD 서버 설정(경로) 견본 |
| `fe/pos/.env.example` | POS 웹 키·매장 코드 자리 |
| `fe/mobile/.env.example` | (사용 안 함) Expo API 주소 |
| `ai/.env.example` | AI 포트·모델 경로 |
