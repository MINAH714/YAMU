# 4. 시연 시나리오

최종 발표 21장 「직접 보여 드릴게요」(약 4분)의 라이브 시연 순서입니다.
**결제 역할극 → 실적관리 → 잔고예보 → 이거 사도 될까** 순서로 진행합니다.

## 준비

| 항목 | 내용 |
|---|---|
| 서버 | `https://yamu.it.kr` (운영 BE · AI · POS 웹) |
| 고객 폰 | YAMU 사용자 앱(release APK, 운영 서버 연결), 시연 계정 **이윤서**로 로그인해 홈 화면에 둠 |
| 매장 태블릿 | Galaxy Tab S6 Lite 가로 화면, 크롬으로 `https://yamu.it.kr` (POS 웹) 접속. 카메라 권한 허용 |
| 발표 PC | 발표 덱, 폰 화면 미러링 창 |
| 시연 데이터 | `be/seed/yoonseo` 시드를 운영에 적재(발표 당일 아침, 담당 김경린). 절차는 `be/seed/yoonseo/README.md` |

시연 전 이윤서 계정 상태(시드 문서 기준):

| 항목 | 값 |
|---|---|
| 계좌 | 국민은행 1개, 잔액 800,000원 |
| 카드 | KB국민 노리 체크(체크), 현대카드 ZERO Edition3 할인형(신용) |
| 노리 전월 실적 | 400,000원 (혜택 조건 충족) |
| 노리 남은 혜택 한도 | 월 15,000원 (공유 한도 20,000원 − 사용 5,000원), 건당 4,000원 |
| 11월 받은 혜택 | 30,500원 (확정 25,200원 + 예정 5,300원) |
| 예정 지출 | 11/20 월세 400,000원, 11/22 통신비 70,000원, 11/23 ZERO 카드값 100,000원 |
| 예정 수입 | 11/25 급여 2,500,000원 |
| 잔고예보 설정 | 30일, 안전 잔액 100,000원 |

화면에 나오는 금액 중 **생활비 예측이 들어가는 값(잔고예보 최저 잔액, 이거 사도 될까 결과)은 AI 예측에 따라 달라집니다.** 리허설에서 확인한 값으로 말합니다.

## 1. 결제 역할극 (약 1분 30초)

스타벅스 직원 역(태블릿 POS)과 야무 사용자 역(폰)이 진행합니다.

| 순서 | 누가 | 화면 | 누를 곳 · 입력 | 화면에 나오는 것 |
|---|---|---|---|---|
| 1 | 직원 | POS 「어느 매장을 열까요?」 | 가운데 왼쪽 **STARBUCKS 역삼점** 카드 | 메뉴판(왼쪽)과 주문 내역(오른쪽) |
| 2 | 직원 | 메뉴판 | **아이스 카페 아메리카노** 2번, **아이스 제주 말차 라떼** 1번, **버터 크루아상** 1번 (위쪽 탭 「전체」에서 모두 보임) | 오른쪽 「주문 내역 4개」, 총 결제금액 **20,000원** |
| 3 | 직원 | 주문 내역 | 오른쪽 아래 파란 **결제하기** | 「결제수단을 골라 주세요」 창 |
| 4 | 직원 | 결제수단 창 | **YAMU페이**의 「일시불」이 골라진 그대로 → 아래 **QR 스캔으로 결제하기** | 「결제 QR을 스캔해 주세요 · 20,000원」, 카메라 화면 |
| 5 | 사용자 | 앱 홈 | 하단 가운데 **결제** 버튼 → **지문으로 결제 코드 열기**(지문이 없으면 「결제 코드 열기」 후 간편 비밀번호 6자리) | 결제 QR · 바코드와 남은 시간 |
| 6 | 직원 | POS 카메라 | 폰의 QR을 태블릿 카메라에 비춤 (카메라가 안 되면 「결제 코드 직접 입력」 칸에 폰 화면에 숫자로 보이는 결제 코드 16자리를 넣고 **이 코드로 결제하기**) | POS: 고객 승인 대기 |
| 7 | 사용자 | 앱 「결제 요청이 왔어요」 → 「결제 확인」 | 카드 목록을 보여 줌: 1순위 **KB국민 노리 체크 · 혜택 4,000원**(야무픽), 2순위 현대카드 ZERO · 160원 | 혜택이 큰 순서로 카드 두 장 추천 |
| 8 | 사용자 | 「결제 확인」 | 화면 아래 파란 버튼 **「(카드사)로 20,000원 결제」** | 「결제하고 있어요」 → **결제를 마쳤어요** |
| 9 | 직원 | POS | — | 영수증 「결제를 완료했어요」 |
| 10 | 사용자 | 앱 「결제를 마쳤어요」 | 아래 **홈으로** | 홈 화면 |

- 노리 체크는 체크카드라 이윤서 국민은행 계좌에서 20,000원이 바로 빠집니다(잔액 800,000원 → 780,000원). 혜택 4,000원은 환급이라 나중에 들어옵니다.
- 승인 시간은 POS 요청 뒤 60초입니다. 시간이 지나면 POS 「승인 시간이 지났어요」 → 앱에서 새 코드를 받아 4번부터 다시 합니다.
- 사용자가 「거절」을 누르면 POS에 「고객이 결제를 거절했어요」가 뜨고 돈은 빠지지 않습니다.

## 2. 실적관리 (약 40초)

이제부터 발표자가 말하고, 야무 사용자 역이 말에 맞춰 앱을 누릅니다.

| 발표자 대사 | 팀원 동작 |
|---|---|
| 이제부터 야무의 다른 기능들을 보여 드리겠습니다. 먼저 실적 관리입니다. | 하단 **실적관리** 탭을 누릅니다. |
| 여기서는 카드별로 이번 달 실적이 얼마나 쌓였는지, 혜택 기준까지 얼마 남았는지 확인할 수 있습니다. | 그대로 둡니다. |
| 카드마다 남은 혜택 한도도 확인할 수 있습니다. | 아래로 내려 **남은 혜택 한도** 줄을 누릅니다(「혜택 한도」 화면). |
| 이번 달 혜택을 얼마나 더 받을 수 있는지 금액으로 보여 줍니다. | 그대로 둡니다. |

## 3. 잔고예보 (약 40초)

| 발표자 대사 | 팀원 동작 |
|---|---|
| 다음은 잔고예보입니다. | 하단 **홈** 탭을 누르고 **잔고예보 보기**를 누릅니다(연결 계좌 전체 · 30일). |
| 월급, 월세, 카드값을 모아 월급날까지 날마다 잔액이 어떻게 될지 보여 줍니다. 안전 잔액은 월급날까지 남겨 두고 싶은 최소 금액인데, 지금은 가장 낮을 때도 그 위에 있습니다. | 그래프와 「안전 잔액」 줄이 함께 보이게 둡니다. |

시드 기준 흐름: 780,000원 → 11/20 월세 −400,000 → 11/22 통신비 −70,000 → 11/23 카드값 −100,000 → 11/24 가장 낮음 → 11/25 급여 +2,500,000. 하루 생활비 예측을 D원이라 하면 11/24 잔액은 `210,000 − 6 × D`원입니다(D = 15,000원이면 120,000원, 안전 잔액 100,000원 위).

## 4. 이거 사도 될까 (약 1분)

| 발표자 대사 | 팀원 동작 |
|---|---|
| 그럼 아까 그 태블릿을 사도 될지 야무에게 물어보겠습니다. | 잔고예보 화면 맨 아래 **이거 사면 잔고는? 비교해 보기**를 누릅니다. |
| 30만 원짜리 태블릿을 넣습니다. | 가격에 `300000`, 「무엇을 사나요 (선택)」에 `태블릿`을 넣고 **다음**을 누릅니다. |
| 체크카드로 오늘 산다고 해 보겠습니다. | 「카드」에서 **KB국민 노리 체크**를 고르고, 일시불과 오늘 날짜는 그대로 둔 채 **사기 전후 비교하기**를 누릅니다. |
| 사기 전엔 가장 낮을 때도 [리허설 값]이 남는데, 태블릿을 사면 [리허설 값]까지 떨어지고 안전 잔액 아래로 내려갑니다. 언제 가장 모자란지, 돈이 빠져나가는 날도 함께 알려 줍니다. | 결과 위쪽을 보여 준 뒤 **빠져나가는 날**까지 천천히 내립니다. |

체크카드는 산 날 바로 300,000원이 빠지므로, 시드 기준(D = 15,000원)이면 가장 낮은 잔액이 120,000원에서 −180,000원으로 내려가 안전 잔액 아래가 됩니다.

## 문제가 생기면

| 상황 | 대응 |
|---|---|
| POS 카메라가 QR을 못 읽음 | 「결제 코드 직접 입력」에 16자리 입력 |
| POS 「결제 결과를 확인하지 못했어요」 | 바로 다시 결제하지 않고 앱 결제 내역을 먼저 확인(두 번 결제 방지) |
| 앱 · 서버가 응답하지 않음 | 백업 영상으로 넘어갑니다 |
| AI 예측 서버가 멈춤 | 잔고예보는 단순 계산(TSB)으로 그대로 나옵니다. 시연은 계속합니다 |
