# 최신 코드에서 LIFE 시드 소비 분석 확인

2026-11-16, `git pull --ff-only origin develop`으로 `2c31e7c7`을 반영했다. 기존 550 시드 변경은 보존했다. 이 결과는 최신 develop + 현재 worktree의 LIFE 시드 기준이다.

격리 MySQL에 사용자 3명의 시드를 apply → 가입 완료 전제 준비 → enrich → verify한 뒤, MockMvc로 인증 필터·실제 컨트롤러·서비스·SQL을 통과하는 API를 호출했다. 실제 앱 로그인/실기기 렌더링 검증은 아니다. 실제 금융망 호출 및 RDS 적재는 하지 않았다. 앱 상단 금액은 현행 `MonthlyReportDto.toSpend`에 따라 `livingSpent`를 사용한다.

5~11월 × 3명 × 월간소비/결제목록/혜택 = **63개 API 요청 HTTP 200**. 세 사용자의 월별 응답이 같은지 검사했고 통과했다. 대표 최인국의 응답과 실행 메타데이터는 [API 결과 JSON](LIFE-CONSUMPTION-API.json)에 있다.

## 11월 화면에서 보이는 내용

- 상단: **11월 1~16일 생활 소비 690,000원**. 지난달 같은 기간보다 350,500원 적게 사용.
- 많이 쓴 곳: 온라인 쇼핑 630,000원(API 91.3%, 앱 반올림 91%), 일반음식점 60,000원(API 8.7%, 앱 9%).
- 이용 혜택 0원. 혜택 상세도 예상/확정/야무픽 추가/놓친 혜택 모두0, 카드별 목록과 놓친 혜택 내역은 빈 목록.
- 결제 내역 12건. 취소·거절은 이 LIFE 초기 구매에 포함하지 않는다.

11월 구매를 온라인 쇼핑과 식당에만 배치한 현재 시드의 결과다. API가 다른 소비 업종을 누락한 결과는 아니다. 분석 화면의 업종 다양성을 더 보려면 향후 시드의 구매 가맹점 구성을 별도로 조정해야 한다. 이번 확인에서 금액·가맹점·혜택 데이터를 바꾸지 않았다.

## 집계 범위에 주의할 부분

7월 가전 900,000원은 LARGE이므로 상단 생활 소비에서 빠지고 전체 카드 소비·결제 목록에는 들어간다. 반면 업종별 `byCategory`는 전체 카드 소비 기준이다. 7월 상단은 1,858,000원이지만 많이 쓴 곳의 온라인 쇼핑 1,741,500원(63.1%), 대형마트 516,000원(18.7%), 일반음식점 396,500원(14.4%)은 전체 2,758,000원 기준이다. 상단 금액과 업종 합계의 범위가 다르므로 같은 합계로 해석하면 안 된다.

월세·급여·계좌이체·카드대금 납부는 이 카드 소비 API 합계에 포함되지 않는다. 카드대금 이중 소비 집계는 없다. 이 항목들은 계좌 원장/예보에 해당한다.

혜택 상세는 최신 앱이 `source=YAMU`로 요청하므로 SEED 구매는 제외한다. 소비 분석 상단의 혜택 요약은 전체 구매를 읽지만, LIFE 시드는 과거 혜택을 소급 생성하지 않아 역시0이다. 실제로 혜택을 받은 YAMU 결제가 추가되기 전에는 비어 있는 혜택 상태를 보여 준다.

자산 흐름은 `/api/asset-flows`의 별도 응답이다. 이번 검사는 소비·건수·혜택 API 결과이며 자산 그래프의 실제 금융망 연결이나 실기기 화면을 검증한 결과가 아니다. 실제 시작 자금 근거를 동기화하고 자산 시드를 적용하는 순서는 [전달 문서](LIFE-HANDOFF.md)를 따른다.
