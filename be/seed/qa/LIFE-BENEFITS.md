# LIFE 혜택 소급 적용 — 2026-11-16 기준

최신 개정: 4~10월 혜택은 QA_HISTORY 근거로 확정 완료이며, 11/8 IBK GS25 즉시 할인 2,200원을 추가했다. 아래 최초 검증 기록 중 '지급 기록 없음/예정 유지/체크 승인액 불변' 설명은 개정 전 상태다. 최신 값과 기존 운영 데이터 반영 명령은 [혜택 개정 절차](LIFE-BENEFIT-REVISION.md)를 따른다.

최인국·남윤주·박준수의 야무 가입일은 **2026-04-01 KST**이다. 가입일 전 소비는 연결된 카드의 과거 이력으로 유지하므로 소비 분석은 2025-12부터 확인할 수 있다. 가입일 이후 234건을 YAMU 구매로 분류한다. 기존 구매 원금·카드·가맹점·날짜·시각·생활 패턴·카드사 실적 시드는 유지한다.

## 계산 기준

현재 저장된 카드 카탈로그와 RecommendationInputAssembler / CardBenefitCalculator를 그대로 사용한다. 테스트 전용 QaLifePolicyReplay에서 2026-11-16 현재 정책의 유효 범위를 승인된 과거 시나리오로 투영한다. 운영 정책 날짜·계산 엔진·리포트 API는 수정하지 않았다. 과거 실제 약관을 재현한다는 의미는 아니다.

거래를 날짜·슬롯순으로 처리하고, 전월 실적과 월별·일별 한도 사용을 누적한다. 쿠팡은 온라인, 나머지는 기존 오프라인 구매로 설정한다. 기본 모의 구매 사실과 기존 처음 카드 직접 구매 기준만 재사용한다. 카드 추천 순위를 꾸며 넣지 않으므로 야무픽 추가 혜택은 0원이다.

완료되고 배분이 확정된 계산만 payment_benefit와 payment_limit_usage에 기록한다. 한도 집계는 모든 과거 월에도 저장한다. 조건 미확인 31건은 제외 사유를 산출물에 남기고 임의의 할인·지급액을 생성하지 않는다. GS25의 상품 구성·중복 적용과 일부 Mr.Life 거래 조건이 여기에 포함된다.

`src/main/resources/qa/life-benefits.json`은 DB ID 대신 상품 내 혜택·한도 코드를 사용하는 재현 가능한 계산 결과다. 통합 테스트가 현재 엔진으로 다시 계산해 전체 결과와 비교한다. 정책 변경 시 이 검사가 실패하므로 카탈로그 변경 후 검증 없이 기존 결과를 재사용하지 않는다. 시드 fingerprint에도 전체 결과를 포함하므로 기존 데이터셋에 조용히 덮어쓰지 않는다.

## 로컬 검증 범위

격리된 Testcontainers MySQL과 MockMvc를 사용한다. 금융망 입출금은 Mockito로 차단하고 호출되지 않았는지 검사한다. RDS 연결·적재, 실제 금융거래, 원격 반영은 하지 않는다.

3명 × 12개월 × 소비 분석·결제 내역·혜택 리포트 API를 호출하고, 가입 전 혜택 0 / 가입 후 매월 혜택 양수 / 엔진 결과와 리포트 합계를 대조한다. 계정별 카드 ID를 제외한 응답도 동일해야 한다. 세 계정·아홉 계좌의 과거 원장 연결, 음수 잔액 방지, 청구와 할인 배분 일치, 재실행 멱등성, QA 신규 구매 보존을 함께 검사한다.

API 응답: `LIFE-BENEFITS-API.json`. 오프라인 계좌·월별 청구 산술: `LIFE-VALIDATION.txt`. 테스트 결과 요약: `LIFE-BENEFITS-VALIDATION.json`.
