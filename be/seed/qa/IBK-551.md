# IBK나라사랑카드 GS25 현장할인 QA — S15P31E103-551

## 적용 범위

실제 상품 IBK나라사랑카드(CHECK, IBK/기업은행 003)의 2026-11-01 이상 2026-12-01 미만(KST) QA 정책이다. 전체 혜택 계산 완료를 의미하지 않는다. 신규 발급 우대는 제외한다.

## 미확인 및 미지원

- 새 혜택의 원 미만 처리·계산 순서·취소 후 횟수 복원은 미확인이다. GS25 모의 정책을 복사하지 않는다.
- All in One 편의점 일 횟수: IBK 안내 2회와 BC 안내 1회가 충돌한다. NULL로 유지한다.
- GS25 현장할인과 계좌 환급의 병행은 확인했으나 환급 계산 기준액이 할인 전/후인지 미확인이다.
- 전월 실적은 저장된 월 실적을 참조한다. IBK의 실시간 실적 인정·취소 접수월 차감은 아직 미지원이며 미확인 인정액을 합산하지 않는다. 기존 공통 취소의 원거래월 복원 정책을 IBK 공식 정책으로 주장하지 않는다.
- 교통/철도·버스/카카오T: 후불 교통·전용 채널 없음.
- 통신/구독·게임: 자동납부·공식 앱 결제 여부 및 접수 자료 없음.
- CGV/놀이공원/TOEIC·교보: 예매·온라인 및 연간 횟수 자료 없음.
- Npay: 실제 Npay 결제·포인트 지급 연동 없음. 현금 1원으로 환산하지 않음.
- 이마트24 품목 혜택/메가오더: 품목 및 주문 채널 자료 없음.
- NOL 포인트/쏘카 쿠폰/지니·SPOTV·왓챠 이용권/해커스·월부 쿠폰: 외부 멤버십·쿠폰 연동 없음.
- PX/군급여·현역 패키지: 자격·급여·이용처 검증 없음. QA 사용자는 해당 자격 false.
- 금융 수수료/환전·ATM/보험·장례: 결제 추천 엔진 밖의 서비스.
- 신규 발급 우대: 명시적 범위 제외. 슈마커 9월 종료 프로모션: 11월 적용 제외.

### S15P31E103-601 프로젝트 계산 정책 (2026-11-17 사용자 지시)

GS25 검증 POS에서 전월 실적 8만원 이상 25만원 미만이면 현장할인과 나라 편의점 환급을 각각 할인 전 원금으로 계산한다. 현장할인은 대상 품목 원금, 편의점 환급은 거래 원금 전체가 기준이다. 도시락 5,500원+김밥 3,300원은 현장할인 880원, 예상 CASHBACK 880원, 총 추천 1,760원, 승인/즉시 출금 7,920원이다. CASHBACK 지급 일정은 미확인이며 이번 변경은 환급 배치나 실제 입금을 수행하지 않는다.

원금 기준은 이번 사용자 승인에 따른 프로젝트 정책이다. 공식 안내의 중복 혜택 소개를 공식 정산 계산식 확인으로 해석하지 않는다. 10% 계산 결과가 정수 원인 요청만 계산하고 정수 원 사전 검증으로 소수 절사를 추정하지 않는다. 현장할인 일 1회, 나라 편의점 월 2회·건별 1천원 및 사용량을 적용한다. 한도 예약·중복 승인 방지·전액 취소 복원은 기존 모의 결제 원장을 사용한다. 환급 월 횟수도 전액 취소 시 복원하는 프로젝트 정책이며 공식 취소 정산 기준으로 주장하지 않는다.

`IBK_ORIGINAL_AMOUNT_CASHBACK_POLICY` 사유와 후보 `benefitNotice`로 이 기준 및 후속 환급임을 알린다. All in One 일 횟수 충돌이나 다른 서비스의 미확정 계산까지 완료한 것은 아니다.

미지원 혜택이 해당 거래에 적용될 가능성이 있으면 DATA_INSUFFICIENT로 남긴다. 다만 S15P31E103-601의 사용자 승인(2026-11-17)에 따라, GS25 지정 품목과 보유자 자격이 확인되고 현장할인이 별도의 일 한도를 가진 STACK 혜택일 때는 미확정 나라/All in One 편의점 환급과 분리해 현장할인만 추천·승인에 반영한다. 결과는 PARTIAL_READY이며 후보의 `benefitNotice`와 저장된 issues에 미확정 환급 제외를 남긴다. 환급 혜택과 해당 한도는 승인에 전달하지 않는다. 현장할인 한도 소진 시 확인된 부분은 0원이지만 추가 환급까지 없다는 뜻은 아니다.

품목 미확인, 보유자 자격 미확인, 다른 미지원 혜택, 공유 한도·택일·전환 정책은 이 예외로 우회하지 않는다. 신규 발급 우대·미확정 환급의 계산/절사/취소 정책을 새로 정하지 않는다. Mr.Life와 현장할인 금액이 같으면 기존 동률 규칙을 따른다.

## POS 검증값

서버가 상품 코드·정수 수량(1~99)·등록 가격·총액을 검사한다. 클라이언트가 할인 대상액을 지정하지 않는다.
최초 장바구니를 거래 JSON에 저장하며, 승인 시 재추천에서도 같은 품목을 사용한다.
품목 순서만 바뀐 재시도는 동일 요청, 동일 금액이라도 다른 품목은 다른 요청으로 판정한다.

| 품목 | 원금 | 즉시할인 | 출금 기대값 |
|---|---:|---:|---:|
| 제육볶음 도시락 1개 | 5,500 | 550 | 4,950 |
| 포카칩 1개 | 1,700 | 0 | 1,700 |
| 도시락+포카칩 | 7,200 | 550 | 6,650 |
| 생수 1개 | 1,100 | 110 | 990 |
| 이미 당일 할인 1회 사용 후 도시락+포카칩 | 7,200 | 0 | 7,200 |
| 첫 혼합 결제 전액 취소 후 재결제 | 7,200 | 550 | 6,650 |

전액 취소 환불액은 원금 7,200원이 아니라 실제 출금액 6,650원이다. 같은 승인·취소 키 재송신은 중복 출금·입금하지 않는다.
비대상 품목만 결제해 할인액이 0원이면 일 할인 횟수를 사용하지 않는다.

- 대상 확정: 삼각김밥, 샌드위치, 도시락, 김밥, 생수, 콜라.
- 비대상: 포카칩, 초코칩, 젤리.
- 분류 미확인: 컵라면, 떡볶이, 바나나맛우유. 포함된 장바구니는 IBK 할인액을 미확인으로 남긴다. POS의 넓은 메뉴 분류만으로 공식 대상 여부를 단정하지 않는다.
- 품목이 없는 구형 요청도 IBK 할인액 미확인이다. 전체 금액 10%나 0원으로 바꾸지 않는다.
- 앱 추천/승인 화면과 거래 내역에서 할인액을 확인한다. POS의 품목 표시 자체는 기존 주문 내역을 사용한다.

## 인프라 전달·초기화

1. **SSAFY 금융망에** 세 사용자별 국민·신한·기업은행 계좌를 생성하고 회원 키와 실제 계좌 정보를 준비한다. 기업은행 계좌는 다른 사용자의 계좌와 공유하지 않는다.
2. 로컬/운영용 입력을 각각 분리하고 datasetKey·회원·계좌를 다르게 한다. 견본의 `REPLACE_...`와 `example.invalid`는 실제 바인딩으로 교체한다. 실제 입력은 커밋하지 않는다.
3. 기존 01/02/03 카탈로그 후 `be/seed/05-ibk-narasarang.sql`을 같은 연결에서 오류 시 중단 방식으로 실행한다. 자동 Flyway/seedLocal에는 등록하지 않았다.
4. v3 입력으로 기존 `plan → apply → 정상 가입·계좌 3개 연결·카드 4장 등록 → enrich → verify`를 실행한다. 실행법은 [README](README.md)를 따른다.
5. 새 POS와 백엔드를 함께 배포해야 상품별 할인이 계산된다. 실제 SSAFY 입출금·앱 화면 검증은 적재 후 진행한다. 자동 테스트의 은행 응답은 격리된 가짜 은행이며 실제 금융망 거래를 발생시키지 않는다.

초기화는 원본 입력으로 `reset`, 삭제는 `purge`를 사용한다. 대상은 dataset 소유권으로 정하고 이름으로 삭제하지 않는다.
reset은 PIN·기기·계좌 연결을 지우므로 재가입이 필요하다. 실제 금융망 잔액·입출금 이력은 reset/purge로 복원되지 않는다.
운영 중 테스트 결제만 되돌릴 때는 정상 전액 취소를 사용한다. 결과 불명 금융 요청은 먼저 해결한다.
공용 IBK 상품·정책은 사용자 purge로 삭제하지 않는다.
