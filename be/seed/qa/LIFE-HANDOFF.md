## 시작 자금을 두 번 계산하지 않는 연결

1. 합성 원장은 2025-12-01~2026-11-15이며 마지막 잔액이 국민105만/신한90만/기업30만 원이다.
2. 실제 SSAFY 원장은 최초 실제 거래 전 0원에서 시작한다. 추후 별도 승인된 시작 자금 입금은 실제 원장에 그대로 보존한다.
3. `fundingExternalId`로 지정한 실제 입금 후 잔액이 합성 종료 잔액과 같은지 검사한다. 합성 잔액 + 실제 입금으로 더하지 않는다. 과거 구간은 QA_SYNTHETIC, 11/16부터는 SSAFY 한 출처만 선택한다.
4. `qa_seed_funding_boundary`에 해당 거래 ID와 해시를 연결한다. 같은 사용자·계좌, 최초 실제 날짜 11/16, 유효 FIRST_TRANSACTION coverage, 실제 기초잔액0, 지정 입금 후 잔액을 모두 확인한다. 가입 인증 등 준비 거래가 같은 날 먼저 있으면 준비 완료 후 입금 거래를 명시적으로 선택한다.
5. 입금 미실행·근거 미확인·날짜 불일치·잔액 불일치·음수 합성 잔액이면 적용을 중단한다. 실제 이력 충돌로 근거가 무효화되면 합성 표시도 중단한다. 현재 잔액을 읽어 과거를 재작성하지 않는다.

현재 실제 계좌는 전달받은 준비 결과상 전부 0원이다. **이번 작업에서는 금융망 조회·입금·출금·이체·회원/계좌 생성·RDS 적재를 실행하지 않는다.** 기존 3회원·9계좌를 재사용하며 중복 생성하지 않는다. 실행 날짜가 11/16을 지나거나 준비 거래의 최초 날짜가 다르면 입력을 임의 변경하지 말고 전환 범위를 다시 검토해야 한다.

## 파일과 실행 준비

- `life-persona-1/2/3.example.json`: 각 사용자 소유권. 계좌번호는 비실제 숫자 견본이고 userKey는 REPLACE 자리표시자다. 단독 DB 적용은 거절된다.
- `QA_SEED_ENCRYPTED_BINDINGS_FILE`: 이미 준비된 `qa550-finance-bindings.encrypted.json` 경로만 환경변수로 제공한다. CLI는 기존 CryptoKeys와 지정 AAD로 메모리에서만 해독한다. 평문 중간 파일을 만들지 않는다. 이름·회원ID·은행·끝4자리 일치를 확인하며 원본의 잔액 필드는 현재 잔액 근거로 사용하지 않는다.
- 기존 `QA_SEED_*`, `YAMU_CRYPTO_*` 설정을 안전한 환경변수로 주입한다. 키나 전체 계좌번호를 명령행·콘솔·MR에 쓰지 않는다. 다른 암호화 키로 재암호화된 바인딩을 임의 사용하지 않는다.
- `life-assets.example.json`: 인프라 담당자가 해당 dataset/persona의 실제 연결 계좌 ID와 명시적으로 확인한 시작 자금 거래 ID로 채운다. 국민·신한·기업에 각각 한 파일을 만든다. 임의 transaction ID나 현재 잔액으로 채우지 않는다.

BE 폴더에서 아래 두 명령은 오프라인이고 DB·금융망을 호출하지 않는다.

```powershell

.\gradlew.bat -I seed/qa/qa.init.gradle seedQa -PqaCommand=plan -PqaFile=seed/qa/life-persona-1.example.json
```

실제 시작 자금 입금이 별도 승인되어 완료된 뒤: **11/16 거래는 11/17 이후** 실제 이력 동기화로 근거 확인 → 자산 전용 plan → apply → verify. 현행 일말 복원기는 조회 당일 거래를 확정 과거 이력으로 저장하지 않으므로, 11/16 당일에는 현재 잔액을 볼 수 있어도 합성 과거 연결은 아직 적용할 수 없다. 이 날짜 규칙을 우회하지 않는다. 원장 생성은 기존 CLI를 재사용하며 LIFE 모드에서는 실제 저장된 SEED 구매·과거 PAID 청구와 템플릿을 대조한다. 다른 소비·급여·월세 extraEvents를 중복 주입하지 않는다.

## 반복과 사용자별 초기화 범위

각 사용자 dataset이 독립적이다. 동일 apply/enrich는 기존 진행 상태를 보존한다. 새 QA 구매는 기존 ACCUMULATING 청구에 추가되며 42만 원으로 덮어쓰지 않는다. 날짜나 입력이 달라진 재적용은 해시 검사로 거절한다.

실제 이력 stream 생성 전에는 사용자별 기존 reset으로 가입 전 상태까지 초기화할 수 있다(그 사용자 PIN·기기·계좌 연결도 재설정). 다른 두 사용자는 보존한다. 실제 이력 stream 생성 후에는 기존 보호 정책대로 전체 reset/purge를 거절한다. **사용자/계좌별 자산 전용 reset은 합성 이력과 자금 연결만 제거하고 실제 이력·가입·PIN·카드·구매를 보존한다.** 실제 QA 구매까지 없애고 금융망 잔액까지 시작 상태로 되돌리는 기능은 이번에 추가하지 않았다. 실제 금융 거래는 DB reset으로 되돌릴 수 없다.
