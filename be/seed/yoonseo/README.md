# 이윤서 · 2026-11-18 스타벅스 발표 시드

이 디렉터리는 **운영 서버에서도 명시적으로 실행할 수 있는 합성 시연 데이터 도구**다. 서버 시작 시 자동 적재하지 않는다. Flyway·스케줄러·웹 서버도 시작하지 않는다. 실제 운영 적재는 별도로 실행해야 한다.

현재 작업 브랜치의 옛 스키마가 아닌 **배포 대상 최신 서버의 스키마·암호화 코드**를 사용한다. 권장 실행 방식은 배포할 Spring Boot jar를 `run.sh`에 전달하는 것이다. 계좌 원장·QA 소유권·청구할인 배분 마이그레이션이 없는 서버에서는 `check`가 실패한다. 이 도구는 필요한 테이블을 임의로 만들지 않는다.

## 설계와 화면

**v2 변경:** 확정 혜택이 충분히 보이도록 LOCA LIKIT 2.0을 추가했다. 현재 `INACTIVE`로 자동 추천에서 제외한다. 8~10월 각각 가전·가구 대형 구매 2,000,000원 × 국내 1.2% = 확정 할인 24,000원, 11월 구매 2,100,000원 × 1.2% = **25,200원**이다. 반올림이 필요 없는 정확한 정책 금액이므로 처음 제안한 25,000원에서 200원 조정했다. 매월 16일 납부 완료된 청구서·할인 배분·합성 출금 이력을 함께 넣는다. 과거부터 보유한 자금으로 대형 구매를 했다는 시나리오이며, 합성 기초 잔액을 역산해 마감 800,000원은 유지한다. 일상 소비가 아닌 계획된 대형 구매이므로 `LARGE/USER`로 분류한다. 실적·혜택 리포트에는 포함되며 일상 생활비 예측에서는 분리된다.

### 화면에서 기대하는 값

- 스타벅스 주문: 아메리카노 4,700원 × 2 + 제주 말차 라떼 6,300원 + 버터 크루아상 4,300원 = **20,000원**.
- 추천: 노리 환급 4,000원, ZERO 청구할인 160원. 새 결제 자체는 시드에 넣지 않는다.
- 11월 시연 전: **30,500원 = 확정 25,200원 + 예정 5,300원**, 추천 추가 혜택 4,800원. 시연 결제 후 **34,500원 = 확정 25,200원 + 예정 9,300원**, 추천 추가 혜택 8,640원.
- 8·9월 리포트는 각각 36,000원(확정 24,000원), 10월은 **36,806원(확정 24,806원)**이다.
- 카드별·업종별 리포트, 이번 달/전월 비교, 실적관리, 결제 내역, 가계부 일정, 자산 흐름에 필요한 관련 행을 함께 넣는다.
- 등록일 이후 합성 앱 결제는 `source=YAMU`, 등록 전 7월은 `SEED`. 모든 결제의 `merchant_context_snapshot.source=YOONSEO_DEMO_V1`, `synthetic=true`로 식별한다. **실제 운영 고객의 실거래가 아니므로 사업 지표에서는 QA 소유권으로 제외해야 한다.**
- 데이터에 포인트 혜택은 없다. 화면을 채우려고 두 카드에 없는 혜택을 만들지 않는다. 놓친 혜택 역시 0원이며 임의 실패 거래를 만들지 않는다.

### 혜택 확정 표시의 현재 한계

서버는 일반 CASHBACK을 승인 원장만으로 확정 처리하지 않는다. 따라서 과거 환급 입금 합성 이력이 있어도 리포트에서는 노리 혜택이 **확정 전**으로 표시될 수 있다. 이 시드는 `QA_LIFE_550` 같은 다른 데이터셋 전용 확정 예외를 사칭하지 않는다. ZERO의 확정은 실제 `card_bill` / `bill_item` / `bill_item_discount` 관계로 표시한다. 노리 환급을 확정으로 보여주려면 별도 일반 환급 확정 처리 기능이 필요하며, 이 시드에 임의 정책을 넣지 않았다.

### 잔고예보는 목표값을 고정하지 않는다

하루 15,000원은 **완료 3개월 평균과 목표**다. 최신 운영 서버의 미래 생활비는 AI 또는 TSB의 최근 소비 예측이므로 꼭 15,000원이 되지는 않는다. 등록일·검증일·최근 결제에 따라서도 달라진다.

11/18 결제 직후, 하루 예측을 `D`라 하면 11/24 보수적 잔액은 `780,000 − 470,000 − 100,000 − D×6`이다. D=15,000이면 120,000원이다. 11/25 일말은 여기에 급여 2,500,000원과 하루 생활비를 반영한다. **4,000원 환급은 입금 예정일을 추측해 예보에 더하지 않는다.** 기기 등록 과정에서 금융망에 인증 입금 1원이 생기면 잔액·예보도 그만큼 증가한다.

## 계좌 입출금과 금융망의 경계

금융망에 과거 날짜로 입출금을 만들어 넣지 않는다. `prepare`는 **오늘 날짜의 80만 원 초기 입금 1건**만 만든다. 월급·월세·생활비·저축 이체·과거 환급은 별도 `QA_SYNTHETIC` 원장으로 적재하며 매 거래의 전후 잔액이 연속적이다. 마감 잔액은 80만 원이다. 실제 초기 입금 행은 `SSAFY` 원장에 응답 그대로 넣고 `qa_seed_funding_boundary`로 두 원장의 연결 근거를 남긴다. 초기 입금 80만 원을 과거 합성 잔액에 다시 더하지 않는다.

계좌 이력은 자산 흐름/잔액 복원 기능에서 사용하는 저장 원장이다. **금융망 원본 거래내역 조회에는 합성 과거 거래가 나타나지 않는다.** 현재 저장 스키마에는 거래 설명 칸이 없으므로 이력 행의 개별 설명을 꾸며 저장하지 않는다. 사람이 확인할 거래 의미는 `YoonseoPlan.Movement.label` 및 계획 생성으로 확인할 수 있다.

## 준비 파일과 환경

1. `input.example.json`을 `input.private.json`으로 복사한다. 공개 견본에는 키·PIN·계좌·카드번호가 없다.
2. **11/18 적재라면 `historyThrough`를 `2026-11-17`로 변경**한다. 11/17 리허설은 `2026-11-16`이다. 과거 합성 원장 다음 날에 전용 금융 계좌를 준비하고 적재한다. 날짜를 허위로 바꾸지 않는다.
3. `environment.example`의 변수 이름에 맞춰 대상 서버의 실제 DB 연결·암호화 키·금융망 API 키를 비밀 환경변수로 주입한다. 운영에 로컬 키를 복사하지 않는다. Linux에서는 개인 파일을 `chmod 600`으로 보호한다.
4. JDK 17 이상이 있는 관리 환경에서 **정확히 대상 서버에 배포된 jar**로 실행한다. 배포된 서비스나 테이블을 변경하는 명령이 아니다.

```bash
# be/seed/yoonseo 위치. 아래는 실행 순서이며 실제 값은 비밀 설정에서 주입한다.
cp input.example.json input.private.json
chmod 600 input.private.json

# 금융망 준비: 별도 전용 회원/KB 계좌 생성 및 800000원 초기 입금.
# YOONSEO_PREPARE_BANK=true 필요. 기존 private binding을 덮어쓰지 않는다.
bash run.sh /absolute/yamu-server.jar prepare /absolute/input.private.json YoonseoBankPrepare

# 데이터 계획 → 금융망/스키마/소유권 사전 조회 → DB 적재 → 검증
bash run.sh /absolute/yamu-server.jar plan /absolute/input.private.json
bash run.sh /absolute/yamu-server.jar check /absolute/input.private.json
bash run.sh /absolute/yamu-server.jar apply /absolute/input.private.json
bash run.sh /absolute/yamu-server.jar verify /absolute/input.private.json
```

`apply`에는 `YOONSEO_SEED_MAINTENANCE=true`와 **정확한 DB 이름**인 `YOONSEO_EXPECTED_DATABASE`가 필요하다. 신규 시연 사용자가 적재 완료 전에 로그인하거나 관련 워커에 처리되지 않도록 적용한다. 연결 DB는 모든 INSERT가 하나의 트랜잭션이다. 실패하면 부분 사용자·결제·원장이 남지 않는다. 일반 서버는 시작하지 않으며 로깅에 키·PIN·계좌번호를 출력하지 않는다.

Spring Boot 소스 체크아웃을 사용하는 PowerShell 대안:

```powershell
# 대상 서버의 be 디렉터리에서 실행. 이 디렉터리를 해당 체크아웃에 복사하거나 절대경로로 지정.
.\gradlew.bat --quiet -I C:/path/yoonseo/run.init.gradle yoonseoSeed -PseedCommand=plan -PseedInput=C:/private/input.private.json
# check/apply/verify도 seedCommand만 변경. 금융망 준비는 아래와 같이 별도 main 사용.
.\gradlew.bat --quiet -I C:/path/yoonseo/run.init.gradle yoonseoSeed -PseedMain=YoonseoBankPrepare -PseedCommand=prepare -PseedInput=C:/private/input.private.json
```

### 이미 존재하는 데이터와 재실행

- 같은 datasetKey·동일 비밀 입력으로 다시 실행하면 검증 후 `UNCHANGED`. 결제/금융망 입금을 다시 만들지 않는다.
- 다른 datasetKey인데 이름/전화·생년월일/금융망 회원/계좌/카드가 기존 사용자와 충돌하면 중단한다. **현재 로컬 이윤서(user 5)의 데이터나 로그인 상태를 변경하지 않는다.**
- 이미 사용한 계좌(예: 잔액 780,001원)를 준비된 80만 원 계좌로 간주하지 않는다. 별도 신규 전용 금융망 계좌를 사용한다. 자동 잔액 보정·초기화·삭제 명령은 없다.
- 금융망 쓰기 전 private journal에 의도를 저장한다. 응답 불명이면 같은 요청을 무조건 재전송하지 않는다. 생성 회원 조회/전용 계좌 목록/입금 원장으로 결과를 대조한다. 해결되지 않으면 journal을 유지하고 확인한다. 저널/입력 파일은 서로 다른 작업자가 공유 실행하지 않는다.
- 금융망에는 DB 롤백이 적용되지 않는다. DB 적재 실패 시 이미 준비된 계좌를 지우거나 다시 입금하지 말고, 같은 파일로 원인을 해결한 뒤 재실행한다.
- 입력이 바뀌면 HMAC 비교로 중단한다. 실적·원장·혜택을 운영에서 직접 UPDATE해 재시연하지 않는다. 새로운 시연용 dataset과 회원으로 준비한다.

## 검증

순수 계획 테스트는 외부 서비스 없이 실행한다:

```powershell
.\gradlew.bat --quiet -I seed/yoonseo/run.init.gradle yoonseoSeed -PseedMain=YoonseoSeedTest -PseedCommand=plan
```

통합 테스트는 이름이 `yoonseo_test_`로 시작하는 **별도 빈 DB**에 최신 스키마와 비개인정보 카드 카탈로그만 넣고 실행한다. 기존 사용자 DB에는 실행할 수 없다. `YOONSEO_TEST_JDBC_URL` 및 DB 사용자 환경변수가 필요하다. `-PseedCommand=integration`으로 실행하며 금융망은 가짜 입력 근거를 사용하고 호출하지 않는다. 테스트 안에서 실제 서버 `ReportService`와 추천 스냅샷 역직렬화를 검증한다. 산출물은 `build/yoonseo-seed/benefit-report-november.json`이다.

확인 범위: 월 실적/평균·일별 잔액·원금/청구할인/청구액 정합성, 실제 혜택 리포트 조회, 추천 내역 DTO 호환, 재실행 중복 방지, 데이터셋 소유권 충돌 거절, 부분 INSERT 실패 롤백. 테스트 결과와 운영 적재 성공은 별개다. 운영 배포 후에는 `check → apply → verify`와 앱의 카드/혜택/예보 화면을 확인한다. 본 시드는 로그인 테스트를 반복하지 않는다.

### 2026-11-17 검증 결과

아래는 v1 당시 기록이다. **v2 최신 통합 검증은 387개 통과**했고 실제 ReportService에서 시연 전 30,500원·확정 25,200원, 10월 36,806원·확정 24,806원을 확인했다. 결제 147건, 합성 입출금 170건(11/16 마감)이다. 기존 로컬 시연 결제 1건을 포함하면 11월 총 34,500원이다. 배포 견본 datasetKey를 v2로 변경했으며 기존 v1 운영 데이터를 자동 덮어쓰지 않는다.

최신 로컬 서버의 컴파일된 클래스와 MySQL의 격리 DB `yoonseo_test_final`에서 **378개 검증 통과**. 11/16까지의 결제 143건·합성 입출금 166건을 적재하고 마감 잔액 800,000원, 청구액 100,000원을 확인했다. 순수 계획 검사에는 11/17까지의 계획도 포함한다. 동일 데이터 재실행은 `UNCHANGED`, 다른 연결의 동시 잠금 획득은 차단됐다.

실제 `ReportService` 결과는 11월 합계 5,300원·추천 추가 혜택 4,800원·카드 2개, 10월 합계 12,806원·확정 청구할인 806원이다. JSON 결과는 `build/yoonseo-seed/benefit-report-november.json`, `benefit-report-october.json`에서 확인한다.

이번 검증에서는 금융망 준비 API를 실행하지 않았으며 운영 DB에도 적재하지 않았다. Linux 배포 jar 실행 스크립트와 새 사용자의 앱 화면·실시간 추천/AI 예보는 배포 환경에서 추가 확인해야 한다. 테스트는 금융망 응답을 가짜 근거로 대체했으며 기존 로컬 사용자의 계좌·로그인은 변경하지 않았다.

### 같은 날 추가한 로컬 앱 검수

이후 사용자의 앱 확인 요청으로, **로컬 전용 일회성 어댑터**에서 기존 이윤서의 과거 합성 이력 109건을 이 설계로 교체했다. 이 어댑터는 운영 패키지에 포함하지 않는다. 교체 전 로컬 DB를 백업했으며, 기존 사용자·기기 로그인·계좌·카드와 실제 시연 결제 1078번은 보존했다. 금융망에는 읽기 조회만 했다. 거래 이력 API는 실제 서버와 동일한 `inquireTransactionHistoryList`로 수정했고 HTTP 200 / H0000 응답을 확인했다.

Android 앱에서 확인한 값(11/17, 기존 스타벅스 결제 포함):
