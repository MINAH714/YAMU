# 가입 시연용 페르소나 시드

회원가입은 **시드에 있는 사람만** 할 수 있습니다(10/30 결정). 앱에서 본인인증 → 계좌 고르기·1원 인증 → PIN → 기기 등록까지 가입을 시연하려면, 가입 직전 상태(PENDING)의 페르소나가 DB에 미리 있어야 합니다. 이 로더가 그 페르소나를 넣습니다.

카드 상품·혜택과 이미 가입을 마친 테스트 사용자는 [README.md](README.md)의 시드(`load.ps1`)가 넣습니다. 이 로더는 그 위에 **가입 전 페르소나만** 더합니다.

## 넣는 것과 넣지 않는 것

| 표 | 넣는 값 |
|---|---|
| `app_user` | `PENDING`, 이름·생년월일·휴대폰(암호문·조회 해시)·SSAFY 회원 ID·userKey(암호문). PIN·본인인증 시각은 비움 |
| `user_card` | `PENDING`, `linked_account_id` 없음. 카드사가 정한 계좌(`issuer_account_*`: 은행 코드·조회 해시·끝 4자리)와 신용카드 결제일(`payment_day`)을 적음. 카드 확인 → 등록을 시연할 카드 |
| `payment_transaction` | 카드 등록 전 6개월 모의 소비(`source = SEED`, `APPROVED`). 아래 「등록 전 모의 소비」 |
| `card_monthly_performance` | 위 결제의 달별 합계를 카드마다 이번 달까지 한 줄씩(카드 등록 화면의 "등록 전 실적") |
| `card_bill`·`bill_item` | 위 신용카드 결제 중 아직 출금되지 않았을 청구서(`ACCUMULATING`)와 회차(`PENDING`). 아래 「등록 전 신용카드 청구서」 |
| 넣지 않음 | `linked_account`(가입 중 SSAFY 계좌 목록에서 골라 연결), `user_device`(가입의 마지막 단계) |

연결 계좌(`linked_account`)는 넣지 않습니다. 계좌는 SSAFY에만 두면 가입할 때 목록에 나옵니다.

카드에는 **카드사가 정한 출금·결제 계좌**(`account`)와 **신용카드 결제일**(`paymentDay`)을 적습니다(10/30 결정, 실제 카드처럼 카드사가 정함). 계좌번호 원문은 저장하지 않고, 카드 등록 때 사용자가 가입 중 연결한 계좌와 해시로 대조해 자동으로 붙입니다. 그래서 카드 계좌는 **그 페르소나의 SSAFY 계좌 중 하나**여야 하고, 로더가 넣기 전에 확인합니다.

## 왜 SQL 파일이 아닌가

- 휴대폰·userKey·카드번호 칸은 **서버의 암호화 키**로 만든 암호문과 조회 해시가 들어갑니다. 키는 환경마다 다르고 깃에 올릴 수 없어서, 서버 설정을 그대로 읽는 코드로 넣습니다.
- SSAFY 회원·계좌는 금융망에만 있어, 넣기 전에 userKey로 계좌 목록을 읽어 실제로 있는지 확인합니다.

## 준비

1. 로컬 DB가 떠 있고 카드 카탈로그가 들어가 있어야 합니다(`docker compose up -d`, [README.md](README.md)의 시드).
2. 페르소나마다 **SSAFY에서 회원과 수시입출금 계좌(잔액 포함)를 미리 만듭니다.** 받은 회원 ID와 userKey를 파일에 적습니다.
3. SSAFY API 키가 앱 설정에 있어야 합니다(`application-local.yml`의 `yamu.fin-api.api-key` 또는 환경변수 `SSAFY_API_KEY`).
4. 견본을 복사해 값을 채웁니다. `persona.local.json`은 깃에 올라가지 않습니다.

   ```powershell
   cd be
   Copy-Item seed\persona.example.json seed\persona.local.json
   ```

### 파일 항목

| 항목 | 필수 | 설명 |
|---|---|---|
| `label` | | 로그에 쓸 이름표(예: `A 직장인`). 개인정보를 넣지 않습니다 |
| `name` · `birthDate` · `phone` | ✅ | 앱 본인인증에 넣을 값과 같아야 합니다. 번호는 숫자 10~11자리 |
| `ssafyMemberId` · `ssafyUserKey` | ✅ | SSAFY에서 만든 회원 |
| `cards[].productName` | ✅ | `card_product.product_name`. 이름이 여러 카드사·종류에 겹치면 `issuerCode`·`cardType`도 넣습니다 |
| `cards[].cardNo` | ✅ | 숫자 16자리. 카드 확인 화면에 넣을 번호 |
| `cards[].expiry` | | `YYYY-MM`. 저장할 칸이 없어 형식만 확인합니다 |
| `cards[].issuerStatus` | | `NORMAL`(기본)·`SUSPENDED`·`EXPIRED`. 정지·만료 카드 시연용 |
| `cards[].account.bankCode` | ✅ | 카드사가 정한 계좌의 SSAFY 은행 코드(숫자 3자리) |
| `cards[].account.accountNo` | ✅ | 그 계좌번호(하이픈 허용). 이 페르소나 SSAFY 계좌 목록에 있어야 합니다 |
| `cards[].paymentDay` | 신용카드 ✅ | 결제일 1~27. 체크카드는 넣지 않습니다 |

## 실행 (be 폴더에서)

```powershell
# 넣기. 같은 사람(휴대폰·생년월일)이 이미 있으면 건너뜁니다.
.\gradlew.bat bootRun --args="--spring.profiles.active=local,persona-seed"

# 시연을 처음부터 다시: 아직 PENDING인 페르소나만 지우고 다시 넣습니다.
.\gradlew.bat bootRun --args="--spring.profiles.active=local,persona-seed --reset"
```

- 웹 서버는 뜨지 않고, 다 넣으면 종료합니다. 실행 중인 서버가 있어도 괜찮습니다.
- 끝에 페르소나마다 결과가 한 줄씩 나옵니다: `CREATED`·`RESET`·`SKIPPED_EXISTS`·`SKIPPED_NOT_PENDING`·`FAILED`.
- 종료 코드: `0` 모두 성공·건너뜀, `1` 실패한 페르소나가 있음, `2` 파일을 읽지 못함.

## 등록 전 모의 소비 (2026-11-05, S15P31E103-255)

가입 시연에서 카드를 등록하면 잔고예보 생활비가 바로 보이도록, 카드 등록 전 6개월치 소비를 함께 넣습니다(`PersonaSpendingHistory`). 잔고예보는 체크카드 SEED 결제를 "첫 SEED 결제일부터 카드 등록 전날까지" 생활비로 씁니다([docs/be/forecast.md](../../docs/be/forecast.md) 「생활비 원천 계약」).

- **기간**: (이번 달 − 6개월)의 1일부터 시드를 넣는 날 전날까지(한국 날짜). 그래서 시드를 넣은 뒤 가입·카드 등록을 하면 완료 3개월 평균(SEED·HIGH)이 나옵니다.
- **가입 시연은 시드를 넣은 날 하세요.** 넣은 날부터 카드 등록 전날까지는 결제가 없어 생활비에서 소비 0원인 날로 셉니다. 예: 11/5에 넣고 12/10에 등록하면 11월이 4일치만 있는 달이 돼 3개월 평균이 약 19만 원 낮아지고, 카드 등록 화면에 12월 실적 행도 없습니다. 날이 지났으면 `--reset`으로 다시 넣습니다(아직 PENDING이면 같은 값으로 다시 들어감). 초기화 없이 다시 돌리면 `SKIPPED_EXISTS` 메시지에 이 안내가 붙습니다.
- **체크카드**(첫 체크카드 1장): 평일 커피·점심·편의점·배달, 주말 마트·영화·올리브영으로 다 찬 달마다 60만~70만 원(넷플릭스·큰 지출 제외, 이번 달은 지난 날수만큼). 확률로 뽑은 뒤 70만 원을 넘으면 결제를 빼고 60만 원에 모자라면 편의점 결제를 더해 맞춥니다. 금액을 비율로 늘리면 마트 결제가 "직전 3개월 중앙값의 10배"를 넘어 큰 지출로 빠지기 때문입니다. 넷플릭스 13,500원 매달 5일(3번째 달부터 반복 지출로 생활비에서 빠짐), 2개월 전 15일 쿠팡 129만 원 1건(100만 원 초과라 큰 지출로 빠짐).
- **신용카드**(첫 신용카드 1장): 매주 토요일 온라인 쇼핑, 3·17일 주유, 25일 통신비(SKT 55,000원), 3개월 전 20일 90만 원 3개월 할부 1건. 잔고예보 생활비에는 들어가지 않습니다(신용카드는 청구로 반영).
- **금액**: 10원 단위로 흩뜨립니다. 같은 카드·가맹점·금액이 서로 다른 3개 달에 나오면 반복 지출로 빠지는 규칙 때문에, 같은 가격의 일상 소비가 생활비에서 빠지지 않게 하려는 것입니다(규칙 개선은 후속 작업).
- **같은 값**: 난수 대신 SSAFY 회원 ID·날짜·순번의 해시로 정해, 같은 사람을 같은 날 다시 넣으면 같은 결제가 들어갑니다.
- **실적**: 달마다 넣은 결제 금액의 **단순 합**입니다. 카드사 실적 인정 규칙(제외 거래 등)은 적용하지 않습니다.
- **가맹점**: 카드 카탈로그 시드(`01-card-catalog.sql`·`02-card-catalog-ab20.sql`)의 브랜드를 씁니다. 없으면 그 페르소나는 `FAILED`입니다.
- 소비 분류(`spending_class`)는 비워 둡니다. 잔고예보가 읽을 때 자동으로 채웁니다.
- 생활비가 보이려면 페르소나 파일에 **체크카드가 1장 이상** 있어야 합니다.

## 등록 전 신용카드 청구서 (2026-11-09, S15P31E103-371)

위 신용카드 소비로 아직 출금되지 않았을 청구서를 함께 넣습니다(`PersonaSeedBills`). 이게 없으면 카드 등록 화면에 "지난달 실적"은 보이는데 잔고예보·청구서 화면에 이번 결제일 카드값 출금이 없습니다(운영 앱 점검 B-06, S15P31E103-357).

- **규칙**: 신용 승인과 같습니다. 카드 결제일과 상품의 이용기간 마감 일수(없으면 14일)로 청구 월을 정하고, 할부는 개월 수로 나눠 나머지를 마지막 회차에 붙이며, 출금 예정일은 결제일을 영업일로 보정합니다. 청구할인은 없습니다.
- **넣는 범위**: 출금 예정일이 **시드를 넣는 날 이후**인 청구 월의 회차만 넣습니다. 그 전 회차는 YAMU를 쓰기 전에 이미 낸 것으로 봅니다(출금 완료 이력은 출금 계좌가 있어야 만들 수 있어 넣지 않음).
- **예**: 결제일 14일, 11/9에 넣으면 11월 청구서(10/1~10/31 사용분 + 8/20 할부 3회차, 11/16 출금. 11/14가 토요일)와 12월 청구서(11/1~11/8 사용분, 12/14 출금)가 생깁니다.
- **상태**: 모두 진행 중(`ACCUMULATING`)입니다. 시드 때는 카드에 출금 계좌가 없어 확정할 수 없습니다. 가입·카드 등록으로 계좌가 붙으면:
  - 잔고예보에는 등록 직후부터 출금이 보입니다(진행 중 청구서는 카드의 지금 계좌로 읽음).
  - 이용기간이 끝난 청구서(위 예의 11월)는 청구 확정 작업(`bill-confirm`, 매일 00:30)이 확정합니다. 그 전까지 청구서 화면에는 "진행 중"으로 보이므로, 시연 직전에 확정해 두려면 관리자 수동 실행을 그 사용자만 대상으로 돌립니다.

    ```
    POST /api/admin/jobs/bill-confirm/run   (관리자 키 헤더)
    {"userId": <시연 계정 user_id>}
    ```

  - 정기 작업이 켜져 있으면(`BILLING_JOBS_ENABLED=true`) 결제일에 시연 계정의 SSAFY 계좌에서 **실제로 출금**됩니다. 시연 전 계좌 잔액을 확인합니다.
- SEED 결제는 취소할 수 없어 이 회차가 환급으로 바뀌지 않습니다.
- **잔고예보에 카드값을 예정 지출로 따로 넣지 않습니다.** 이 청구서와 같은 출금이 두 번 잡힙니다.
- 이미 가입을 마친 계정에는 넣지 않습니다. 가입 전(PENDING) 페르소나를 `--reset`으로 다시 넣을 때 생깁니다.

## 동작 규칙

| 상황 | 결과 |
|---|---|
| 처음 넣음 | `CREATED` |
| 이미 있음(초기화 안 함) | `SKIPPED_EXISTS`. 아무것도 바꾸지 않습니다. 아직 PENDING인데 등록 전 모의 소비를 오늘 전에 넣었거나 없으면 `--reset` 안내가 붙습니다 |
| 초기화 + 아직 PENDING | `RESET`. 가입 중 연결한 계좌·카드와 등록 전 모의 소비(`source = SEED`)·실적·시드 청구서까지 지우고 다시 넣습니다(새 user_id). SEED가 아닌 결제가 있으면 지우지 않고 `FAILED` |
| 초기화 + 가입을 마침(ACTIVE)·탈퇴 | `SKIPPED_NOT_PENDING`. 지우지 않습니다 |
| SSAFY 계좌 0개, 키 오류, 금융망 실패 | `FAILED`. 그 페르소나만 넣지 않습니다 |
| 카드 계좌가 그 회원의 SSAFY 계좌 목록에 없음, 신용카드 결제일 없음, 체크카드에 결제일 | `FAILED`. 메시지에 카드 순번·은행 코드만 나옵니다(계좌번호 없음) |
| 카드 상품을 못 찾음·이름이 겹침 | `FAILED`. 카드 카탈로그 시드와 `issuerCode`·`cardType`을 확인합니다 |
| 입력 형식 오류, 같은 파일에 같은 사람 두 번 | `FAILED` |
| 두 실행이 동시에 같은 사람을 넣음 | 한쪽은 `CREATED`, 다른 쪽은 `SKIPPED_EXISTS` (DB UNIQUE가 막음) |

- 페르소나마다 트랜잭션이 따로라 한 명이 실패해도 나머지는 들어갑니다.
- 로그에는 순번·이름표·결과만 남깁니다. 이름·번호·userKey·카드번호는 남기지 않습니다.
- SSAFY 회원·계좌는 지울 수 없어서 초기화해도 그대로 둡니다. 같은 회원으로 다시 넣으면 됩니다.

## 시연 순서 예

1. 로더로 페르소나를 넣습니다.
2. 앱에서 그 페르소나의 이름·생년월일·번호로 본인인증 → 화면의 인증번호 입력.
3. 계좌 목록에서 고르고 1원 인증 → SSAFY 거래내역에서 코드를 확인해 입력.
4. PIN 설정 → 기기 등록 → 가입 완료(ACTIVE).
5. 카드 등록 뒤 잔고예보에서 결제일 카드값 출금을 확인합니다. 청구서 화면에 확정된 청구서로 보이려면 위 「등록 전 신용카드 청구서」의 확정 수동 실행을 돌립니다.
6. 다시 하려면 `--reset`. 가입을 마친 사람은 초기화되지 않으니, 처음부터 보여 줄 페르소나는 따로 두거나 DB를 초기화합니다.
